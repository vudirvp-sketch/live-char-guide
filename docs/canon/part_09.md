## 9.1 Шкала качества и 5 быстрых проверок

### Шкала качества карточки (4 уровня — паттерны ошибок)

4 зоны качества показаны в VS-EMBED E14 выше (Критический 0–25% / Слабый 25–50% / Хороший 50–85% / Отличный 85–100%) с подробными критериями. Таблица ниже — типичные паттерны ошибок для каждой зоны (дополняет E14, не дублирует критерии).

| Уровень | Типичные паттерны ошибок |
|---------|--------------------------|
| **Критический** (0–25%) | поведенческие якоря без T→A→P, OCEAN с 4+ полюсами, нет Anti-godmoding |
| **Слабый** (25–50%) | дефект (FLAW) = прилагательное, Examples не демонстрируют голос, SPINE не связана с якорями |
| **Хороший** (50–85%) | дефект = поведение, ≥2 Examples с голосом, связь SPINE→якоря |
| **Отличный** (85–100%) | 14/14 предразвёрточных проверок пройдены, телесность (Embodiment) во всех якорях, Format Lock консистентен во всех Examples |

**РЕКОМЕНДАЦИЯ:** Цель — «Хороший» уровень. «Критический» = переписать. «Слабый» = точечные доработки по Decision Tree. «Отличный» = полировка для продакшна.

**Ссылка:** Полная пред-деплой валидация (быстрая проверка — 5 пунктов + полная проверка — 14 пунктов) — см. `[ref: §9.11]`.

## 9.2 Правило одного изменения

`data-section: p9_one_change_rule`

<!-- difficulty: BASIC -->

**ПРАВИЛО:** Никогда не меняйте более одного параметра за раз. Иначе вы не узнаете, что именно помогло. Изменили → протестировали 5–10 сообщений → оценили → только потом следующее изменение.

**Применение:** относится ко всем правкам карточки — параметры сэмплирования (RepPen, PP, Temperature), структура Anchors, Examples, SPINE-цепь. Не объединяйте правки в одном тест-цикле. Сам диагноз перед правкой ставят по дереву решений — `[ref: §9.6 — Дерево решений]`.

## 9.6 Дерево решений

`data-section: p9_decision_tree`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Decision tree -->

**Сценарий:** симптом-таблица (`[ref: §9.5]`) не помогла локализовать проблему или симптом затрагивает несколько блоков одновременно — последовательный пошаговый поиск с ветвлением «Если да → / Если нет →». Для структурной проверки по блокам карточки → `[ref: §9.3 — Чек-лист диагностики]`; для пред-деплой валидации → `[ref: §9.11 — Пред-деплой валидация]`.

Если симптом-таблица не помогла локализовать проблему, используйте пошаговое дерево. Формат: Симптом → Проверка → Если да → / Если нет → следующая проверка. Три самых частых симптома разобраны до конца — полный маппинг «проверка → диагноз» ниже; остальные группы симптомов — в таблице выше.

| Симптом | Проверка | Если да → | Если нет → |
|---------|----------|-----------|------------|
| Персонаж теряет голос | утечка голоса в Description? | Удалить голос из Description (AP-3 Voice-in-Desc) | → Следующая проверка |
| | Достаточно ли Examples? | Добавить 2–3 Examples | → Следующая проверка |
| | Совпадает ли формат Examples и Greeting? | Унифицировать формат (Format Lock) | → Проверить Voice Contamination |
| Персонаж годмодит | Есть ли Anti-godmoding в SP? | Добавить 2 строки (AP-6 No-Anti-Godmoding) | → Усилить Influence Boundary |
| Персонаж «слишком идеальный» | Есть ли FLAW в SPINE? | Добавить FLAW + FLAW-linked якорь (Anchor) | → Проверить OCEAN: >2 полюса? → `[ref: part_05.md §5.3 — OCEAN Warning]` (AP-15 OCEAN-Overload) |
| Повторы в ответах | RepPen > 1.10? | Fix → AP-5 (RepPen-High) | → Проверить PP: >0? (AP-7 PP-Leak) |
| | Используете Ollama/LM Studio? | Сменить интерфейс (PP=0.7 hardcode) | → Проверить якоря на дублирование |
| Модель теряет внутреннюю логику персонажа | Есть ли у персонажа внутренний процесс? | Fix → `[ref: part_06.md §6.2 — CoT]` (AP-10 CoT-Overload) | → Проверить SPINE на консистентность (AP-9 SPINE-Broken) |

### Три базовых симптома: полный маппинг (канонический источник дерева E13)

Ниже — полный маппинг трёх базовых симптомов: от проверки к диагнозу с анти-паттерном и эталонным разделом. Это канонический источник дерева E13 (`TEXTUAL_CANONICAL`): визуальная версия в preamble Part 9 показывает те же ветвления «Нет → / Да →», значения = §9.6. | Симптом | Проверка | Ветка «Нет» → диагноз | Ветка «Да» |
|---------|----------|----------------------|------------|
| Персонаж дрейфует после 5–10 сообщений | У персонажа есть рабочие Anchors? | **Отсутствует структура Anchors** — AP-2 (отсутствующая цена), AP-8 (призрак без якорей) | → следующая проверка |
| | SPINE причинно согласован? | **Нарушенная цепь SPINE** — AP-9 (сломанный SPINE) | **Дрейф голоса (доминирование недавнего чата)** — AP-11 (переплетение голосов); `[ref: part_07a.md §7A.5 — Author's Note]` (E16) |
| Голос звучит типично / неразличимо | Голос записан только в Examples? | **Утечка голоса в Description/SP** — AP-3 (голос в Description), AP-11 (переплетение голосов) | → следующая проверка |
| | Достаточно ли диалоговых примеров (3+)? | **Недостаточно образцов голоса** — E01 (структура блоков карточки, `[ref: part_01.md §1.2]`), E07 (иерархия источников голоса, `[ref: part_03.md §3.2]`) | **Проблема параметров сэмплирования** — AP-5 (RepPen > 1.10), E17 (`[ref: part_07a.md §7A.6 — Sampling Parameters]`) |
| Персонаж игнорирует действия пользователя | Anti-godmoding присутствует в SP? | **Отсутствует Anti-godmoding** — AP-6 (отсутствие анти-годмодинга), E02 (конвейер сборки SP, `[ref: part_07a.md §7A.13]`) | → следующая проверка |
| | Персонаж использует протокол Embodiment? | **Embodiment отсутствует** — E04 (протокол телесности, `[ref: part_02.md §2.4]`), директива 2 `[ref: part_07a.md §7A.2 — Embodiment First]` (E08) | **Нарушение границы влияния** — директива 5 `[ref: part_07a.md §7A.2 — Influence Boundary]` (E08), E03 (формат якоря T→A→P, `[ref: part_02.md §2.1]`) |

## 9.10 12B-специфичные проблемы

`data-section: p9_12b_issues`

<!-- difficulty: EXPERT -->

**Сценарий:** карточка развёрнута на 12B-модели (Gemma 3 12B, Mistral Nemo 12B, Qwen 2.5 14B и подобные модели класса 12–14B актуальных поколений) — 12B-специфичные симптомы (быстрая деградация голоса, игнорирование SPINE, OOC, повторы, неспособность к CoT) с фиксом под архитектурные ограничения модели. Для общих симптомов (не 12B-специфичных) → `[ref: §9.5 — Таблица симптомов]`; для пошаговой диагностики → `[ref: §9.6 — Дерево решений]`; для рекомендованных параметров генерации под 12B → `[ref: part_07a.md §7A.6 — Sampling Parameters]`.

12B модели имеют ограничения, требующие особого подхода. Рекомендуемые параметры генерации для 12B → `[ref: part_07a.md §7A.6 — Sampling Parameters]`. Язык SP для 12B — многоуровневый: для ранних 12B с <64K словарём (Llama 2, Qwen 1.x) английский оптимален; для актуальных 12B–14B с ≥128K словарём (Gemma 3 12B, Mistral Nemo, Qwen 2.5 14B) язык карточки допустим — см. `[ref: part_07a.md §7A.2 — SP language rule]`.

### Симптомы 12B

| Симптом | Причина | Решение |
|---------|---------|---------|
| Голос деградирует быстро | Ограниченная память | Более явные Anchors, короче Examples |
| Модель игнорирует SPINE | Недостаточная ёмкость | Упростите SPINE до FLAW + ложь (LIE) |
| OOC моменты | Контекст overflow | 4K-Fallback Protocol |
| Повторы фраз | Паттерн-зависимость | RepPen 1.02–1.05 (12B-диапазон — `[ref: part_07a.md §7A.6]`), разнообразьте Examples |
| Неспособность к CoT | Архитектура модели | Tier 0-1 CoT только, без XML |

## 9.11 Пред-деплой валидация

**Сценарий:** карточка собрана, но ещё не развёрнута — формальная валидация перед деплоем (Быстрая проверка 5 пунктов — обязательно; Полная проверка 14 пунктов — рекомендуется для карточек с SPINE и OCEAN). Для диагностики уже развёрнутой карточки → `[ref: §9.3 — Чек-лист диагностики]`; для эмпирического тестирования после деплоя → `[ref: §9.7 — Тестовые сценарии]`.

### Быстрая проверка (5 пунктов — обязательно)

Базовая версия (таблица по блокам) — `[ref: §9.3 — Чек-лист диагностики]`; визуальная версия — блок «5 быстрых проверок перед развёртыванием» в VS-EMBED E14 (§9.1). Ниже — применение к карточке Елены.

### Пример: Быстрая проверка для Елены

| Проверка | Результат |
|----------|-----------|
| ☐ PP = 0.0 | ✓ Presence Penalty = 0.0 |
| ☐ Voice только в Examples | ✓ Дескрипторы голоса только в Examples — «саркастичная» показана через поведение, не описана в `<identity>` (→ §3.1 изоляция голоса) |
| ☐ Price в каждом Anchor | ✓ Все 6 якорей имеют T→A→P (напр: Искренняя забота → отшучивается → руки дрожат) |
| ☐ Format Lock | ✓ Система A: `*action*` «speech» во всех Examples + Greeting |
| ☐ Anti-godmoding | ✓ "Never speak or act for `{{user}}`" + позитивная формулировка |

**Итог:** Елена проходит Быструю проверку — voice descriptors only in Examples. PP / Anchors / Format Lock / Anti-godmoding — ✓. → Полная проверка (14 пунктов) для карточек с SPINE и OCEAN.

### Полная проверка (14 пунктов — рекомендуется)

Пункты 1–5: см. `[ref: §9.3 — Чек-лист диагностики]` (быстрая проверка) — визуальная версия: VS-EMBED E14 (§9.1).

| # | Проверка | Ожидаемый результат |
|---|----------|---------------------|
| 6 | CORE DIRECTIVES | Все 7 директив присутствуют |
| 7 | Spatial & Anatomical Lock | Директива #3 в CORE DIRECTIVES |
| 8 | Язык SP | SP language rule per §7A.2 (12B <64K → English; 12B ≥128K → either; 32B+/API → card language). RP content always in card language |
| 9 | Immersion Boundary | OOC-защита в SP |
| 10 | GHOST-цепь | GHOST→LIE→FLAW→NEED→WANT логична |
| 11 | Tone Frame | Присутствует для нетривиальных сеттингов |
| 12 | OCEAN ≤ 2 полюса | Не более 2 экстремальных значений |
| 13 | Lorebook параметры | Depth/Probability/Cooldown в рекомендованных диапазонах |
| 14 | CoT ≤ 3 якоря | Не более 2–3 CoT-якоря |

### Пример: Pre-Deploy для Выщербленного (полная карточка)

**Структурная проверка Выщербленного (5 пунктов — отлична от универсальной Быстрой проверки выше):**

> Это structural check SP/Description/Examples/Greeting для конкретной карточки, не universal parameter checklist.

| Проверка | Результат |
|----------|-----------|
| ☐ SP содержит Anti-godmoding | ✓ "Never speak or act for `{{user}}`" |
| ☐ SP содержит Format Lock | ✓ "Dialogue: `*action*` «speech»" |
| ☐ Description ≤ 800 токенов | ✓ ~650 токенов |
| ☐ Examples содержат ≥ 2 примера | ✓ 3 примера + CoT |
| ☐ Greeting демонстрирует голос | ✓ "Добро пожаловать в Архив. Чего ищете... в других?" |

**Полная проверка:**

| Проверка | Результат |
|----------|-----------|
| ☐ CORE DIRECTIVES: 7 директив | ✓ Все 7 в формате `<CORE_DIRECTIVES>` |
| ☐ SPINE: 5 элементов связаны | ✓ GHOST→LIE→FLAW→NEED→WANT цепь логична |
| ☐ Слои призрака: 3 tier | ✓ G1/G2/G3 определены с якорями |
| ☐ CoT-якоря: ≤ 3 | ✓ 2 CoT-якоря (Tier 2 + Tier 3) |
| ☐ Lorebook: консистентен | ✓ 5 записей без конфликтов с Description |
| ☐ XML: валиден | ✓ Все теги закрыты, структура корректна |
| ☐ Tone Frame: присутствует | ✓ "archival, detached. Memory is currency." |
| ☐ Author's Note: расширенный формат | ✓ State + WANT→NEED + GHOST-activation + Blind Spot + Scene |
| ☐ OCEAN: 1-2 экстремума | ✓ Высокая O, Низкая E |
| ☐ Immersion Boundary | ✓ Присутствует (для 32B+ и API) |

**Итог:** Выщербленный проходит Pre-Deploy полностью.
