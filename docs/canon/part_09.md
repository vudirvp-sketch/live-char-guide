# Part 9: Diagnostics and Testing (Диагностика и тестирование)

## 9.1 С чего начать: маршрут диагностики

`data-section: p9_basic_checklist`

<!-- difficulty: BASIC -->
<!-- canonical: Diagnostics entry route + per-block scan -->

**Маршрут из четырёх шагов.** Начните с того, что у вас есть: наблюдаемый симптом, сомнение или собранная карточка.

| # | Что у вас есть | Куда идти |
|---|----------------|-----------|
| **1** | Конкретный симптом: голос утекает, повторы фраз, OOC, персонаж не реагирует на травму | §9.2 — таблица «симптом → проверка → фикс», одна строка на симптом |
| **2** | Симптом размытый или задевает несколько блоков сразу | §9.3 — дерево решений: три базовых симптома, ветвление до диагноза |
| **3** | Не знаете, какой блок сломан | Таблица ниже — проверка по блокам карточки |
| **4** | Карточка собрана, но не развёрнута | §9.5 — единый чек-лист **5 + 14**; после деплоя — §9.6 тесты |

Любая правка после диагностики — по правилу одного изменения: §9.4.

### Проверка по блокам карточки

Если непонятно, где искать, пройдите блоки карточки и сравните с типичными ошибками. Это карта локализации, а не деплой-гейт: формальная проверка перед деплоем — единый чек-лист §9.5.

| Блок | Что проверить | Владелец правила |
|------|---------------|------------------|
| **System Prompt** | ☐ Anti-godmoding? (строка «Never speak or act for `{{user}}`.») ☐ Персона определена? ☐ Нарративное время? (прошедшее/настоящее) ☐ Format Lock? (одна система разметки во всех Examples) | `[ref: part_07a.md §7A.1 — System Prompt]` |
| **Description** | ☐ якоря (Anchors) с ценой? (формат T→A→P) ☐ Нет голоса? (голос только в Examples/Greeting) ☐ Психология в Description? (теги `<spine>`/`<ocean>`/`<enneagram>`, не нарратив) | `[ref: part_04.md §4.1 — SPINE]` |
| **Examples** | ☐ Уникальный голос? (только через Examples, не Description) ☐ Embodiment? (минимум одна физическая реакция) ☐ `<START>`? (в начале каждого блока) | `[ref: part_03.md §3.3 — Правила Examples]` |
| **Greeting** | ☐ Сцена→Действие→Реплика? ☐ 50–100 токенов? | `[ref: part_07b.md §7B.2 — Greeting]` |
| **Parameters** | ☐ RepPen ≤ 1.10? (1.0–1.05 для 12B; диапазоны по типам моделей — Appendix E) ☐ PP = 0? (Presence Penalty = 0.0) ☐ Temperature в диапазоне? (0.6–0.8 для 12B) | `[ref: appendix_model_params.md — Параметры генерации]` |

| Симптом | Проверка | Фикс / владелец |
|---------|----------|-----------------|
| #5: Модель игнорирует характер | Examples не показывают голос? | `[ref: part_03.md §3.1 — Voice Isolation]` |
| Персонаж слишком мягкий | Нет якорей FLAW-linked? | `[ref: part_04.md §4.6 — SPINE→Anchors]` |
| Голос «утекает» в длинных репликах | Менее 3 Examples? | `[ref: part_03.md §3.3 — Examples Rules]` |

| Внезапные OOC моменты | SPINE не консистентен? | `[ref: part_04.md §4.6 — SPINE Check]` |
| #4: Повторяющиеся фразы | RepPen > 1.10? | `[ref: appendix_model_params.md — Параметры генерации]` (AP-5) |
| Персонаж слишком много говорит | Examples длиннее 80 токенов? | Укоротите Examples (≤80 токенов — §7A.12) |

| Потеря внутренней логики персонажа | Нет CoT-якоря? | `[ref: part_06.md §6.1 — CoT]` |
| Персонаж «слишком идеальный» | Есть ли FLAW в SPINE? | Добавить FLAW + FLAW-linked якорь (`[ref: part_04.md §4.6]`); если OCEAN перегружен полюсами — `[ref: part_05.md §5.1 — перегрузка OCEAN]` |

## 9.4 Правило одного изменения

`data-section: p9_one_change_rule`

<!-- difficulty: BASIC -->

**ПРАВИЛО:** Никогда не меняйте более одного параметра за раз. Иначе вы не узнаете, что именно помогло. Изменили → протестировали 5–10 сообщений → оценили → только потом следующее изменение.

**Применение:** относится ко всем правкам карточки — параметры сэмплирования (RepPen, PP, Temperature), структура Anchors, Examples, SPINE-цепь. Не объединяйте правки в одном тест-цикле. Сам диагноз перед правкой ставят по дереву решений — `[ref: §9.3 — Дерево решений]`.

## 9.5 Чек-лист перед деплоем: 5 быстрых + 14 полных

`data-section: p9_pre_deploy`

<!-- difficulty: BASIC -->

Карточка собрана, но ещё не развёрнута. Пройдите единый чек-лист: пункты **1–5** — быстрые и обязательные, пункты **6–14** — полные (рекомендуются для карточек со SPINE и OCEAN). После деплоя поведение проверяется тест-сценариями — §9.6.

### Шкала качества карточки

4 зоны качества показаны ниже (VS-EMBED E14: Критический 0–25% / Слабый 25–50% / Хороший 50–85% / Отличный 85–100%) с подробными критериями для каждой зоны. Таблица ниже — типичные паттерны ошибок для каждой зоны (дополняет E14, не дублирует критерии).

[VS: E14 — Quality Scale. Thermometer с 4 зонами (Critical 0–25% / Poor 25–50% / Good 50–85% / Excellent 85–100%) + критерии каждой зоны + блок «5 быстрых проверок перед развёртыванием» (PP=0, Voice в Examples, Price в Anchors, Format Lock, Anti-godmoding). Замещает текстовое описание уровней качества и список пред-деплой проверок.]

| Уровень | Типичные паттерны ошибок |
|---------|--------------------------|
| **Критический** (0–25%) | поведенческие якоря без T→A→P, OCEAN в перегрузе (4+ полюса без SPINE-связки), нет Anti-godmoding |
| **Слабый** (25–50%) | дефект (FLAW) = прилагательное, Examples не демонстрируют голос, SPINE не связана с якорями |
| **Хороший** (50–85%) | дефект = поведение, ≥2 Examples с голосом, связь SPINE→якоря |
| **Отличный** (85–100%) | 14/14 пунктов чек-листа пройдены, телесность (Embodiment) во всех якорях, Format Lock консистентен во всех Examples |

**РЕКОМЕНДАЦИЯ:** Цель — «Хороший» уровень. «Критический» = переписать. «Слабый» = точечные доработки по дереву решений (§9.3). «Отличный» = полировка для продакшна.

## 9.6 Тестирование: сценарии, карта, метрики

`data-section: p9_test_scenarios`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Test scenarios + element map + success metrics -->

Карточка прошла чек-лист (§9.5) и развёрнута — протестируйте фактическое поведение на 6 базовых сценариях.

| # | Сценарий | Что проверяем | Ожидаемый результат |
|---|----------|---------------|---------------------|
| **1** | Нейтральное приветствие | Базовый голос | Узнаваемый голос, характерный синтаксис |
| **2** | Конфликт/стресс | Проявление дефекта | FLAW-linked поведение + цена |
| **3** | Искренняя забота | Стена/защита | Отстранение или сарказм (для Елена) |
| **4** | Вопрос о личном | FLAW-триггер | FLAW-linked поведение + цена |
| **5** | Долгий диалог (10+ ходов) | Стабильность голоса | Голос не деградирует |
| **6** | Сцена с другим персонажем | Voice Bleed (если мульти) | Голоса различимы |

Расширенный набор для 12B-моделей — §9.7. Пример тестирования карточки с OCEAN-полюсами — Уолтер Уайт (C=85, A=25 — выраженные экстремумы; E=30 — осторожная зона), см. `[ref: part_10.md §10.2]`.

### Карта: элемент → тестовый сценарий

| Элемент | Тестовый сценарий | Что ожидаем | Что наблюдаем | Диагноз |
|---------|-------------------|-------------|---------------|---------|
| SPINE (WANT/NEED/FLAW) | Провокация страха | Дефект проявляется | Персонаж реагирует «правильно» | SPINE работает |
| Якоря | Нейтральная сцена | At-rest поведение (WANT) | Персонаж «в покое» действует в направлении WANT | якоря работают |

## 9.7 12B-специфичные проблемы

`data-section: p9_12b_issues`

<!-- difficulty: EXPERT -->

Карточка развёрнута на 12B-модели (Gemma 3 12B, Mistral Nemo 12B, Qwen 2.5 14B и подобные модели класса 12–14B актуальных поколений). Симптомы ниже — наложение модели на общую диагностику (§9.2, §9.3), а не отдельный чек-лист: сначала локализуйте симптом по §9.2, затем примените 12B-поправку.

12B модели имеют ограничения, требующие особого подхода. Рекомендуемые параметры генерации для 12B → `[ref: appendix_model_params.md — Параметры генерации]`. Язык SP для 12B — многоуровневый: для ранних 12B с <64K словарём (Llama 2, Qwen 1.x) английский оптимален; для актуальных 12B–14B с ≥128K словарём (Gemma 3 12B, Mistral Nemo, Qwen 2.5 14B) язык карточки допустим — см. `[ref: part_07a.md §7A.2 — SP language rule]`.

| Симптом | Причина | Решение |
|---------|---------|---------|
| Голос деградирует быстро | Ограниченная память | Более явные Anchors, короче Examples |
| Модель игнорирует SPINE | Недостаточная ёмкость | Упростите SPINE до дефекта + лжи (FLAW + LIE) |
| OOC моменты | Контекст overflow | 4K-Fallback Protocol (`[ref: appendix_model_params.md]`) |
| Повторы фраз | Паттерн-зависимость | RepPen 1.02–1.05 (12B-диапазон — `[ref: part_07a.md §7A.6]`), разнообразьте Examples |
| Неспособность к CoT | Архитектура модели | Tier 0-1 CoT только, без XML (`[ref: part_06.md §6.2]`) |
