# Part 9: Diagnostics and Testing (Диагностика и тестирование)

## 9.1 С чего начать: маршрут диагностики

`data-section: p9_basic_checklist`

<!-- difficulty: BASIC -->
<!-- canonical: Diagnostics entry route + five common errors + per-block scan + flat lookup -->

**Маршрут из четырёх шагов.** Начните с того, что у вас есть: наблюдаемый симптом, сомнение или собранная карточка.

| # | Что у вас есть | Куда идти |
|---|----------------|-----------|
| **1** | Конкретный симптом: голос утекает, повторы фраз, OOC, персонаж не реагирует на травму | Пять самых частых ошибок и таблица «симптом → проверка → фикс» — ниже |
| **2** | Симптом размытый или задевает несколько блоков сразу | Дерево решений: три базовых симптома, ветвление до диагноза |
| **3** | Не знаете, какой блок сломан | Проверка по блокам карточки — ниже |
| **4** | Карточка собрана, но не развёрнута | Единый чек-лист перед деплоем (5 быстрых + 13 полных); после деплоя — тест-сценарии |

Любая правка после диагностики — по одному изменению за раз, с проверкой 5–10 сообщений после каждого.

### Пять самых частых ошибок

С них начинается почти любая сломанная карточка: симптом, причина и исправление. Все пять исправляются в блоках, которые вы уже прошли.

| # | Ошибка | Что видно | Исправление |
|---|--------|-----------|-------------|
| **1** | Персонаж пишет за `{{user}}` | Модель описывает действия, мысли и реплики `{{user}}`; диалог превращается в монолог от двух лиц — в System Prompt нет анти-годмодинга | Две строки в SP: запрет говорить и действовать за `{{user}}` + замена «реагировать только на то, что `{{user}}` делает и говорит» |
| **2** | Голос не соответствует описанию | Персонаж описан как «лаконичный и холодный», а модель отвечает многословно и эмоционально — голос описан в Description вместо того, чтобы быть показанным в Examples | Уберите из Description прилагательные о речи и напишите 2–3 примера диалога, где голос виден: длина фраз, лексика, то, что персонаж не договаривает |
| **3** | Персонаж «слишком идеальный» | Не ошибается, не проявляет уязвимость, реагирует «правильно» на любой стимул — у якорей нет цены | Каждому якорю — цена, наблюдаемая в той же сцене: дрожащие руки, сорванный голос, шаг назад |
| **4** | Повторяющиеся фразы | Одни и те же обороты возвращаются чаще, чем того требует сцена | RepPen ≤ 1.10 (12B: 1.0–1.05); повышайте MinP, а не RepPen |
| **5** | Модель игнорирует характер | Реплики подходят любому персонажу — Examples не показывают голос | 2–3 Examples, в которых голос слышен без описания; ни одного стилистического прилагательного в Description |

### Проверка по блокам карточки

Если непонятно, где искать, пройдите блоки карточки и сравните с типичными ошибками. Это карта локализации, а не деплой-гейт: формальная проверка перед деплоем — единый чек-лист.

| Блок | Что проверить | Признак ошибки |
|------|---------------|----------------|
| **System Prompt** | ☐ Anti-godmoding? (строка «Never speak or act for `{{user}}`.») ☐ Персона определена? ☐ Нарративное время? (прошедшее/настоящее) ☐ Format Lock? (одна система разметки во всех Examples) | Модель пишет за пользователя, путает время, ломает разметку |
| **Description** | ☐ якоря (Anchors) с ценой? (формат T→A→P) ☐ Нет голоса? (голос только в Examples/Greeting) ☐ Психология в Description? (теги `<spine>`/`<ocean>`/`<enneagram>`, не нарратив) | Персонаж не показывает уязвимость, говорит «как все», психология спорит с поведением |
| **Examples** | ☐ Уникальный голос? (только через Examples, не Description) ☐ Embodiment? (минимум одна физическая реакция) ☐ `<START>`? (в начале каждого блока) | Голос звучит типично, в ответах нет тела, границы блоков съезжают |
| **Greeting** | ☐ Сцена→Действие→Реплика? ☐ 40–100 токенов? | Первое сообщение — монолог без сцены или обрывок |
| **Parameters** | ☐ RepPen ≤ 1.10? (1.0–1.05 для 12B) ☐ PP = 0? (Presence Penalty = 0.0) ☐ Temperature в диапазоне? (0.6–0.8 для 12B) | Повторы фраз, дрейф голоса, персонаж «расползается» на новые темы |

### Симптом → проверка → фикс

Плоский поиск: найдите строку со своим симптомом и примените исправление. Если симптом не находится или задевает несколько блоков — дерево решений.

| Симптом | Проверка | Исправление |
|---------|----------|-------------|
| Персонаж слишком мягкий | Нет якорей FLAW-linked? | Добавьте якорь, привязанный к дефекту: тот же триггер, но с ценой |
| Голос «утекает» в длинных репликах | Менее 3 Examples? | 3 примера: базовый, конфликтный и на дефект |
| Персонаж не показывает уязвимость | Нет цены у Anchors? | Цена физическая и внутри сцены: дрожащие руки, сорванный голос, шаг назад |
| Внезапные OOC моменты | SPINE не консистентен? | Проверьте цепь GHOST→LIE→FLAW→NEED→WANT: каждый элемент объясняется предыдущим |
| Персонаж слишком много говорит | Examples длиннее 80 токенов? | Укоротите Examples до ≤80 токенов каждый |
| Модель ломает формат | Нет Format Lock? | Пропишите в SP одну систему разметки и держите её во всех Examples и Greeting |
| Персонаж забывает контекст | Карточка + контекст > контекстное окно? | 4K-Fallback: SP 80–100 · Description 150–200 · два Examples вместе 130–160 · Greeting 50–80 |
| Неестественные переходы | Нет transition sentences? | Добавьте Embodiment-переходы: тело реагирует раньше реплики |
| Потеря внутренней логики персонажа | Нет CoT-якоря? | 2–3 CoT-якоря на ключевые триггеры, остальные — обычные T→A→P |
| Персонаж «слишком идеальный» | Есть ли FLAW в SPINE? | Добавьте FLAW + FLAW-linked якорь; если OCEAN перегружен полюсами — снимите лишние крайности |
| Повторы при PP > 0 в Ollama / LM Studio | Интерфейс захардкожил Presence Penalty? | Смените интерфейс (KoboldCPP, TabbyAPI, vLLM) или выставьте PP = 0.0 |

## 9.5 Чек-лист перед деплоем: 5 быстрых + 13 полных

`data-section: p9_pre_deploy`

<!-- difficulty: BASIC -->
<!-- canonical: Pre-deploy validation (one checklist: quick 5 + full 13) -->

Карточка собрана, но ещё не развёрнута. Пройдите единый чек-лист: пункты **1–5** — быстрые и обязательные, пункты **6–18** — полные (рекомендуются для карточек со SPINE и OCEAN). После деплоя поведение проверяется тест-сценариями.

### Шкала качества карточки

4 зоны качества показаны ниже (VS-EMBED E14: Критический 0–25% / Слабый 25–50% / Хороший 50–85% / Отличный 85–100%) с подробными критериями для каждой зоны. Таблица ниже — типичные паттерны ошибок для каждой зоны (дополняет E14, не дублирует критерии).

[VS: E14 — Quality Scale. Thermometer с 4 зонами (Critical 0–25% / Poor 25–50% / Good 50–85% / Excellent 85–100%) + критерии каждой зоны + блок «5 быстрых проверок перед развёртыванием» (PP=0, Voice в Examples, Price в Anchors, Format Lock, Anti-godmoding). Замещает текстовое описание уровней качества и список пред-деплой проверок.]

| Уровень | Типичные паттерны ошибок |
|---------|--------------------------|
| **Критический** (0–25%) | поведенческие якоря без T→A→P, OCEAN в перегрузе (4+ полюса без SPINE-связки), нет Anti-godmoding |
| **Слабый** (25–50%) | дефект (FLAW) = прилагательное, Examples не демонстрируют голос, SPINE не связана с якорями |
| **Хороший** (50–85%) | дефект = поведение, ≥2 Examples с голосом, связь SPINE→якоря |
| **Отличный** (85–100%) | 18/18 пунктов чек-листа пройдены, телесность (Embodiment) во всех якорях, Format Lock консистентен во всех Examples |

**РЕКОМЕНДАЦИЯ:** Цель — «Хороший» уровень. «Критический» = переписать. «Слабый» = точечные доработки: меняйте по одному параметру за раз. «Отличный» = полировка для продакшна.

## 9.6 Правка и проверка: сценарии, карта, метрики

### Правило одного изменения

**ПРАВИЛО:** Никогда не меняйте более одного параметра за раз. Иначе вы не узнаете, что именно помогло. Изменили → протестировали 5–10 сообщений → оценили → только потом следующее изменение.

**Применение:** относится ко всем правкам карточки — параметры сэмплирования (RepPen, PP, Temperature), структура Anchors, Examples, SPINE-цепь. Не объединяйте правки в одном тест-цикле.

Карточка прошла чек-лист и развёрнута — протестируйте фактическое поведение на 6 базовых сценариях.

| # | Сценарий | Что проверяем | Ожидаемый результат |
|---|----------|---------------|---------------------|
| **1** | Нейтральное приветствие | Базовый голос | Узнаваемый голос, характерный синтаксис |
| **2** | Конфликт/стресс | Проявление дефекта | FLAW-linked поведение + цена |
| **3** | Искренняя забота | Стена/защита | Отстранение или сарказм (для Елена) |
| **4** | Вопрос о личном | FLAW-триггер | FLAW-linked поведение + цена |
| **5** | Долгий диалог (10+ ходов) | Стабильность голоса | Голос не деградирует |

## 9.7 12B-специфичные проблемы

`data-section: p9_12b_issues`

<!-- difficulty: EXPERT -->

Карточка развёрнута на 12B-модели (Gemma 3 12B, Mistral Nemo 12B, Qwen 2.5 14B и подобные модели класса 12–14B актуальных поколений). Симптомы ниже — наложение модели на общую диагностику, а не отдельный чек-лист: сначала локализуйте симптом по таблицам выше, затем примените 12B-поправку.

12B модели имеют ограничения, требующие особого подхода. Язык SP для 12B — многоуровневый: для ранних 12B с <64K словарём (Llama 2, Qwen 1.x) английский оптимален; для актуальных 12B–14B с ≥128K словарём (Gemma 3 12B, Mistral Nemo, Qwen 2.5 14B) язык карточки допустим.

| Симптом | Причина | Решение |
|---------|---------|---------|
| Голос деградирует быстро | Ограниченная память | Более явные Anchors, короче Examples |
| Модель игнорирует SPINE | Недостаточная ёмкость | Упростите SPINE до дефекта + лжи (FLAW + LIE) |
| OOC моменты | Контекст overflow | 4K-Fallback: SP 80–100 · Description 150–200 · два Examples вместе 130–160 · Greeting 50–80 |
| Повторы фраз | Паттерн-зависимость | RepPen 1.02–1.05 (12B-диапазон), разнообразьте Examples |
| Неспособность к CoT | Архитектура модели | Tier 0-1 CoT только, без XML |
