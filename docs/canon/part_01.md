## 1.1 Зачем системный подход?

`data-section: p1_value_proposition`

<!-- difficulty: BASIC -->

Классический подход — интуитивное заполнение Description. Системный подход — причинно-следственная архитектура, где каждый элемент производит наблюдаемое действие. Разница в предсказуемости поведения, а не в стиле описания.

| Параметр | Классический подход | Системный подход (SPINE) |
|----------|---------------------|---------------------------|
| Дрейф голоса (20+ сообщений) | ~40% отклонение от исходного тона | ~10% отклонение при том же токен-бюджете |
| Консистентность поведения | Модель заполняет пробелы дефолтами | Якоря задают конкретные триггеры → модель следует паттернам |
| Токен-эффективность | Description = 500+ токенов общих характеристик | OCEAN: `N:68` = 5 токенов вместо 30 текста |
| Динамика персонажа | Статичное поведение | WANT→NEED сдвиг через Price — персонаж развивается в сессии |

**Методология:** проценты в гайде — эмпирические ориентиры на основе тестирования ~50 карточек на 12B–32B моделях с 32K-словарём (ранние Llama 2, Qwen 1.x, ранний Mistral). Для актуальных 12B–14B моделей со словарём ≥128K (Gemma 3, Qwen 2.5, Mistral Nemo) разрывы меньше. Читайте их как качественные маркеры — стабилен / дрейфует / сломан, — а не как точные измерения.

## 1.2 Базовые блоки карточки

`data-section: p1_card_overview`

<!-- difficulty: BASIC -->

**Карточка персонажа** — документ, который задаёт поведение модели в ролевой игре. Думать о ней нужно как о поведенческом движке: каждый элемент производит наблюдаемое действие, а не украшает описание. Ниже — пять блоков карточки и их бюджеты.

[VS: E01 — Card Anatomy. Стек из 5 блоков карточки (System Prompt / Description / Examples + Anchors / Greeting / Lorebook) с токен-аннотациями «мин/стд/макс» и сводной таблицей бюджета. Значения бюджета общие с канонической таблицей §7A.12 (SHARED_REFERENCE): блок Examples показывает итог — бюджет на один пример × количество примеров; строка Lorebook — объявленная оценка («Est.», Part 7B), не каноническое значение. Замещает текстовое перечисление структуры блоков карточки.]

Сквозной пример гайда — карточка Елены: её элементы разбираются по частям, а целиком она собрана в части 10.

## 1.3 Структурные свойства блоков

`data-section: p1_structure_overview`

<!-- difficulty: BASIC -->

Схема выше показывает блоки и их бюджеты. В таблице — то, чего на схеме не видно: насколько блок влияет на модель и какую долю бюджета занимает. Якоря нарисованы в Examples-зоне, потому что они задают поведение, а Examples — голос, но в карточке это отдельный `<anchors>`-тег внутри Description: отдельного поля Anchors у типового фронтенда нет.

| Блок | Влияние на модель | Доля бюджета |
|------|-------------------|--------------|
| **System Prompt** | Высокое — задаёт рамки | Компактный |
| **Description** | Среднее — контекст | Основной объём |
| **Examples** | Ключевое — паттерны речи | Средний |
| **Якоря (Anchors)** (`<anchors>` в Description) | Ключевое — поведенческие триггеры | Средний — входит в Description |
| **Greeting** | Поддерживающее — тон | Минимальный |

## 1.4 Три ключевых принципа

`data-section: p1_core_rules`

<!-- difficulty: BASIC -->
<!-- canonical: Pattern Matcher rule, 3 key principles (Anchor=T→A→P, Voice only in Examples, Psychology only in Description) -->

Эти принципы обязательны для всех карточек: нарушение любого из них ухудшает генерацию, и никакие другие настройки это не компенсируют.

**ПРАВИЛО:** Фундаментальный принцип: LLM = **сопоставитель паттернов (Pattern Matcher)**, не исполнитель правил. Директива в SP без паттерна в Examples нестабильна на моделях ≤14B (~40–60% следование директивам). Поэтому Examples — главный инструмент, а Description — логика поведения.

1. **Якорь = триггер → действие → цена.** Поведение задаётся якорями, и у каждого якоря есть цена — физическая реакция, наблюдаемая в той же сцене. Без цены якорь остаётся инструкцией: модели нечего скопировать.
2. **Голос — только в Examples и Greeting.** Характер речи модель считывает из примеров диалога, а не из описания. Лингвистический голос (слова, синтаксис, лексика, ритм) живёт в Examples; физическая характеристика голоса (тембр, хрип, механический гул) — часть телесности в Description.
3. **Психология — в Description, компактно, в тегах.** SPINE, OCEAN и Enneagram размещаются в Description как структурированные теги (`<spine>`, `<ocean>`, `<enneagram>`) с числами и короткими пометками, а не развёрнутым текстом. В System Prompt психологии нет места.

**ПРИМЕР:** компактный и нарративный формат OCEAN в Description.

✓ `<ocean>O:72 C:65 E:41 A:38 N:68</ocean>` — пять чисел; модель считывает их как pattern, экстремумы помечаются короткой пометкой после чисел.

✗ *«Елена — любопытная и творческая журналистка, склонна к конфликту и сарказму, тревожная и реактивная…»* — нарратив: токены потрачены, структурной ясности нет.

Если в карточке есть SP, Description, Examples, Greeting — она уже работает: это и есть минимальная рабочая карточка, минимум — четыре блока. Три правила (якорь = T→A→P, голос только в Examples, психология только в Description) — единственное, что нельзя нарушать.

## 1.6 Профиль сборки: шесть вопросов

`data-section: p1_prebuild_checklist`

<!-- difficulty: BASIC -->
<!-- canonical: Pre-build checklist (6 questions) — Build-mode entry instrument (build profile) -->

Ответьте на шесть вопросов до начала работы: они определяют, какие инструменты понадобятся и насколько большой будет карточка.

| # | Вопрос | Варианты | Что это определяет |
|---|--------|----------|--------------------|
| 1 | **Размер модели** | 12B / 32B+ / API | 12B — упор на Examples и якоря, минимальный SP. 32B+ — можно CoT, Author's Note, Lorebook. API — максимум инструментов. |
| 2 | **Контекстное окно** | 4K / 8K / 16K+ | 4K — минимальные бюджеты блоков и 2 Examples. 8K — стандартные бюджеты, 3 Examples, базовый Lorebook. 16K+ — полная карточка, CoT, слои призрака. |
| 3 | **Сложность персонажа** | Простая / Средняя / Экспертная | Простая — четыре обязательных блока. Средняя — плюс один продвинутый инструмент (CoT или Lorebook). Экспертная — слои призрака + CoT + Lorebook. |
| 4 | **Призрак: один или слои** | 1 / 3-tier | 1 — призрак как одно событие. 3-tier — хронология: детство → юность → настоящее. |
| 5 | **CoT нужен?** | Нет / Да | Нет — телесности достаточно как микро-цепочки рассуждений. Да — явный внутренний монолог для триггеров SPINE. |
| 6 | **Lorebook нужен?** | Нет / 1–3 записи / 5+ | Нет — все факты помещаются в Description. 1–3 — контекстные триггеры. 5+ — мир и факты призрака. |

**РЕКОМЕНДАЦИЯ:** Если вы впервые собираете карточку — выбирайте «12B / 8K / Простая / 1 GHOST / без CoT / без Lorebook». Это конфигурация Елены: пять чисел OCEAN, одна строка на элемент SPINE, шесть якорей — три базовых и три FLAW-linked. Бюджет 8K-профиля — ориентир 400–900 токенов. Не пытайтесь сразу строить экспертную карточку: перегрузка Description и утечка голоса — самые частые последствия.
