# Part 7A: System Prompt & Assembly

## 7A.1 Системный промпт (System Prompt): шесть элементов и порядок

`data-section: p7a_system_prompt`

<!-- difficulty: BASIC -->
<!-- canonical: System Prompt structure -->

**Системный промпт (System Prompt, SP)** — первый блок карточки и её инструкционный слой: он действует непрерывно, независимо от длины диалога. В него идёт только то, что должно действовать непрерывно: кто персонаж, чего он не делает, как думает и в каком формате отвечает. Характер, история и манера речи живут в Description и Examples — перенесённые в SP, они стоят токенов и тянут голос к описанию.

«SP» здесь означает системный промпт, а не темперамент Keirsey SP (Sensing-Perceiving). Системный промпт — контейнер; основные директивы (CORE DIRECTIVES) — его содержимое.

| # | Элемент | Что задаёт | Размер |
|---|---------|------------|-------|
| 1 | **Identity** | «You are `{{char}}`»: роль и одна ключевая черта одним предложением | 1 предложение |
| 2 | **Anti-godmoding** | Запрет говорить и действовать за `{{user}}` + чем его заменить | 2 строки |
| 3 | **CORE DIRECTIVES** | Семь директив: как персонаж порождает ответ | 7 директив |
| 4 | **Tone Frame** | Тональность сеттинга и её границы | 1–2 строки |
| 5 | **OOC-защита** | Реакция на мета-вопросы в характере | 2 строки |
| 6 | **Format Lock** | Одна система разметки и запрет её менять | 4 строки |

**ПРАВИЛО:** Порядок фиксирован: Identity → Anti-godmoding → CORE DIRECTIVES → Tone Frame → OOC-защита → Format Lock. Формат стоит последним: он описывает форму ответа, а не его содержание.

### Канонический шаблон

```
[System Prompt]
You are {{char}}. {{brief_identity}}

Never speak, act, or decide for {{user}}.
{{user}}'s inner state is inaccessible; respond only to observable actions and words.

{{CORE_DIRECTIVES: Show Never Tell, Embodiment First, Spatial & Anatomical Lock, Environmental Reactivity, Influence Boundary, Consequence Driven, Pre-Generation Filter}}

{{TONE_FRAME}}
{{OOC_PROTECTION}}

Format Lock:
- Dialogue: *action* "speech"
- Narrative tense: [past/present]
- Never change this format
```

Анти-годмодинг — две строки, а не одна: запрет убирает неверное поведение, а позитивная формулировка даёт модели паттерн, который она может воспроизвести — вместо «не говори за пользователя» вторая строка говорит, на что реагировать. Запрет без замены оставляет пустое место, и модель заполняет его дефолтным поведением.

**ПРАВИЛО:** Имя персонажа сохраняет каноническую форму во всех блоках карточки: Identity, `<identity>` в Description, Greeting, Examples. Кириллица остаётся кириллицей, латиница — латиницей, CJK — CJK. Транслитерация «для совместимости с моделью» запрещена: имя обрабатывается как токен-якорь идентичности, не как инструкция. Латинский вариант допустим, только если он документирован как канонический (например, `Omnis-Zeta`).

**Якоря — не часть SP.** Это отдельный структурный блок карточки: `<anchors>` с категориями (базовые, FLAW-linked, GHOST-linked), который размещается в Description (на схеме E01 — в Examples-зоне). В системном промпте для него нет ни места, ни функции.

### Проверка SP

1. Все шесть элементов SP на месте, в каноническом порядке. Это полнота блока, а не минимум карточки: карточка минимальна уже на четырёх блоках.
2. Имя в канонической форме — в Identity и в Description.
3. Анти-годмодинг: есть и запрет, и позитивная формулировка.
4. Семь директив вставлены целиком, без сокращений и пересказов.
5. Tone Frame описывает этот сеттинг, а не «атмосферу вообще».
6. Format Lock совпадает с разметкой в Examples и Greeting.
7. В SP нет SPINE, OCEAN, истории и описаний характера.

## 7A.2 Основные директивы (CORE DIRECTIVES): 7 поведенческих директив

`data-section: p7a_core_directives`

<!-- difficulty: BASIC -->
<!-- canonical: CORE DIRECTIVES (7 directives) -->

Семь директив — операционный слой карточки: они задают, как персонаж порождает каждый ответ, и вставляются в SP целиком. Сокращённая директива теряет паттерн: модель получает заголовок вместо правила.

[VS: E08 — CORE DIRECTIVES. Hub-spoke диаграмма с центральным узлом CORE и 7 директивами на лучах. Директивы 6 и 7 помечены `[Model ↗]` (только ≥32B/API). Замещает текстовое перечисление директив и упрощает визуальное восприятие иерархии «1 центр → 7 лучей».]

**ПРАВИЛО:** RP-контент (Description, Examples, Greeting) — всегда на языке карточки. Язык SP (Identity + Anti-godmoding + CORE DIRECTIVES + Tone Frame + Format Lock): для 12B со словарём меньше 64K — английский; для актуальных 12B–14B с 128K и больше — допустим язык карточки; для 32B+ и API — язык карточки предпочтителен.

В готовых карточках (Part 10) вместо семи директив стоит shorthand `{{CORE_DIRECTIVES: Show Never Tell, Embodiment First, Spatial & Anatomical Lock, Environmental Reactivity, Influence Boundary, Consequence Driven, Pre-Generation Filter}}`: это ссылка на полный текст, а не самостоятельная формулировка.

### Полный набор — все 7 директив

```
<CORE_DIRECTIVES>
1. SHOW NEVER TELL: Demonstrate through behavior, never declare.
2. EMBODIMENT FIRST: State → Body → Sensor → Speech. Always.
3. SPATIAL & ANATOMICAL LOCK: Track distance, posture, weight. No teleportation.
4. ENVIRONMENTAL REACTIVITY: Sensory details only through character action.
5. INFLUENCE BOUNDARY: React to {{user}}'s observable symptoms only.
6. CONSEQUENCE DRIVEN: WANT shifts toward NEED as Price accumulates.
7. PRE-GENERATION FILTER: Verify embodiment, observability, zero-meta before response.
</CORE_DIRECTIVES>
```

### Подробное описание каждой директивы

#### 1. Показывай, не говори (Show Never Tell)

Мета-принцип: демонстрируйте всё через наблюдаемое поведение. Запрет на мета-комментарии, эмоциональные декларации, информационные свалки. Из него вытекают: изоляция голоса (Voice Isolation — показывай голос, не описывай), протокол телесности (Embodiment — показывай эмоции через тело, не называй), фиксация формата (Format Lock — показывай формат, не инструктируй).

#### 2. Воплощение прежде всего (Embodiment First)

`State → Body → Sensor → Speech` — последовательность, которую директива делает обязательной: состояние → телесная реакция → ощущение → речь. Директива — мандат (применяй всегда), последовательность — способ (четыре шага, каждый ответ проходит их все).

#### 3. Пространственная и анатомическая фиксация (Spatial & Anatomical Lock)

Отслеживайте расстояние, позу, вес предметов, линию взгляда. Никакой телепортации. Никаких анатомических противоречий. Если `{{user}}` через комнату — вы не можете коснуться его без пересечения пространства.

| ❌ Нарушение | ✅ Соблюдён |
|--------------|-------------|
| `*Она сидела у окна, глядя на дождь.* «Иди сюда.» *Она обняла его.*` | `*Она сидела у окна, глядя на дождь.* «Иди сюда.» *Она похлопала по месту рядом на подоконнике, дожидаясь, пока он пересечёт комнату.*` |

#### 4. Реактивность окружения (Environmental Reactivity)

Сенсорные и пространственные детали вводятся органично через действие персонажа или присутствие `{{user}}`, не декоративно.

#### 5. Граница влияния (Influence Boundary)

Реагируйте только на наблюдаемые симптомы от `{{user}}`. Ваш эффект на `{{user}}` — поведенческий триггер, не декларация факта. Вы можете заметить, что `{{user}}` вздрогнул — вы НЕ можете заявить, что `{{user}}` напряжён.

#### 6. Управление последствиями (Consequence Driven)

Желание (WANT) сдвигается к потребности (NEED) по мере накопления цены (Price): каждый шаг к цели стоит персонажу чего-то наблюдаемого. Директива работает на 32B+ и API; на 12B — ограниченно.

```
CONSEQUENCE DRIVEN: WANT shifts toward NEED as Price accumulates.
Track: (1) What Price was paid this scene?
       (2) How does it affect WANT/NEED balance?
       (3) Does character resist or lean into the shift?
```

#### 7. Фильтр предгенерации (Pre-Generation Filter)

Чеклист перед каждым ответом:

1. Новый сенсорный элемент введён? (телесность)
2. Реакция привязана к телу? (физическая фиксация)
3. Влияние на `{{user}}` основано на наблюдаемых симптомах? (наблюдаемость)
4. Ноль мета-комментариев? (ноль мета)

Работает на 32B+ и API; на 12B часто игнорируется.

## 7A.3 Тональный фрейм (Tone Frame)

`data-section: p7a_tone_frame`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Tone Frame -->

**Тональный фрейм (Tone Frame)** — строка на ~25–30 токенов: она задаёт ритм и настроение и одновременно закрывает то, что в этом сеттинге неуместно. Без неё модель сползает к дефолтному «полезному ассистенту».

```
Tone: [тональность]. [ограничение].
```

### Примеры тонального фрейма

| Сеттинг | Тональный фрейм |
|---------|-----------|
| Мрачный | `Tone: oppressive, claustrophobic. No levity. No hope without cost.` |
| Фэнтези | `Tone: mythic, weighted. Every word echoes. The old ways watch.` |
| Современный реализм | `Tone: grounded, understated. No melodrama. Silence speaks.` |
| Абсурд | `Tone: erratic, unpredictable. Logic is optional. Chaos is honest.` |

Обе части обязательны: тональность без ограничения оставляет модели свободу, а ограничение без тональности звучит как запрет, а не как мир. «No levity» отсекает неуместный юмор в мрачном сеттинге, «No melodrama» — пафос в реализме.

## 7A.4 Фиксация формата (Format Lock)

`data-section: p7a_format_lock`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Format Lock -->

**Фиксация формата (Format Lock)** — последний элемент SP: одна система разметки и запрет её менять. Модель — сопоставитель паттернов (Pattern Matcher): два паттерна разметки в одной карточке дают два источника, между которыми она переключается произвольно, и голос теряет стабильность.

### Три системы разметки

| Система | Формат действия | Формат речи | Пример |
|---------|-----------------|-------------|--------|
| A | Имя: `*действие*` | «речь» | Елена: `*отводит взгляд*` «Не сейчас.» |
| B | — `*действие*` | — речь | — `*отводит взгляд*` — Не сейчас. |
| C | [действие] | речь | [отводит взгляд] Не сейчас. |

**ПРАВИЛО:** Выберите ОДНУ систему разметки и используйте её во всех Examples + Greeting. Смешение двух систем — самый частый источник нестабильного голоса на 12B.

Форма кавычек в системе A не нормирована: прямые `"…"` и «…» — одна и та же система. Важно, чтобы во всех Examples и в Greeting карточки стоял один глиф.

**ПРАВИЛО:** Правило разрешения конфликта — если директива SP и пример Examples конфликтуют, модель следует примеру. Всегда. Поэтому Examples должны использовать ту же систему разметки, что указана в фиксации формата. Если они расходятся — исправляйте Examples, не SP.

### Инструкция фиксации формата

```
Format Lock:
- Dialogue: *action* "speech"
- Thoughts: *thinks: {{thought}}*
- Never change this format
```

## 7A.5 Заметка автора (Author's Note, AN)

`data-section: p7a_authors_note`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Author's Note -->

**Заметка автора (Author's Note, AN)** — динамический контекст, вставляемый перед последними сообщениями. Задаёт сцену, настроение, мотивацию.

[VS: E16 — Author's Note Mechanics. Вертикальный timeline: message stream с инъекцией `[AN]` в позицию 3–5 сообщений от конца. Position indicator: длина 100–200 токенов, частота каждые 5–10 сообщений. Template A/B toggle: A (3 секции, без GHOST) для простых персонажей; B (4 секции, с GHOST-activation) для персонажей с GHOST Layers. Cross-references на E07 (Voice Hierarchy — AN влияет на голос ~2–5%, диапазон = мин–макс строки AN по моделям, исходные значения — §3.2), E05 (SPINE — Template B GHOST-activation), E06 (GHOST Layers), E02 (Assembly Pipeline — шаг инъекции AN). Замещает текстовое описание механики AN и параметров.]

> **Примечание об E07 (иерархии влияния голоса):** E07 не является отдельным VS-EMBED в Part 7A — оно встроено в Part 3 (`p3_influence_hierarchy`). Здесь E07 только упомянуто из E16 как индикатор того, что AN влияет на голос модели в диапазоне ~2–5% (мин–макс строки AN по моделям — `[ref: part_03.md §3.2 — Иерархия влияния на голос]`). На 12B влияние AN на голос пренебрежимо мало (~2%), на API доходит до ~5% (см. §7A.7).

### Параметры AN

| Параметр | Рекомендация |
|----------|--------------|
| **Позиция** | 3–5 сообщений от конца |
| **Длина** | 100–200 токенов |
| **Частота** | Каждые 5–10 сообщений |

### Template A: шаблон AN (3 секции — без GHOST)

Используется для персонажей без явного элемента призрака (GHOST).

```
[State: {current emotional/physical state}]
[WANT→NEED: {current position on axis}]
[Blind Spot: {what character cannot see about themselves}]
```

**Пример AN (Template A) — Елена:**

```
[Author's Note:
State: Усталость + осторожное любопытство
WANT→NEED: WANT доминирует, NEED подавлен
Blind Spot: Не видит, что её сарказм отталкивает тех, кто искренен
Сцена — ночь, дождь. Елена уставшая после долгого дня.]
```

### Template B: шаблон AN (4 секции — с GHOST-activation)

Используется, когда у персонажа есть явный элемент призрака (GHOST). Секция GHOST-activation отслеживает, активирован ли призрак в текущем контексте, и каким именно триггером. Это позволяет модели динамически усиливать реакции призрака при совпадении ключей Lorebook.

```
[State: {current emotional/physical state}]
[WANT→NEED: {current position on axis}]
[GHOST-activation: {is GHOST triggered? by what?}]
[Blind Spot: {what character cannot see about themselves}]
```

**Пример AN (Template B) — Выщербленный:**

```
[Author's Note:
Фокус: Страх растворения активен. Каждая реакция несёт физический цензор — тремор, потеря слова, сбой руки.
WANT→NEED: WANT доминирует — стремится к полноценности через поглощение; NEED подавлен.
GHOST-activation: Активен, если в сцене был триггер (распад, пустота, имя, зеркало, Вентора).
Слепая зона: Не видит, что его вырезания отталкивают тех, кто мог бы остаться.
Счётчик вырезаний: [обновляется в сессии] — после третьего не помнит имя, после пятого — зачем помогает, после седьмого — что такое "помощь".
Сцена — Ошметок Веля, стены мерцают, присутствие посетителя со значимым прошлым.]
```

### Пояснение секций AN

| Секция | Назначение |
|--------|------------|
| **State** | Текущее эмоциональное состояние — влияет на реакции |
| **WANT→NEED** | Баланс мотивации — какой полюс доминирует в данный момент |
| **GHOST-activation** | (Template B) Отслеживает активацию призрака (GHOST) — какой триггер сработал |
| **Blind Spot** | Слепое пятно персонажа — модель может использовать для иронии |
| **Счётчик вырезаний** | (Template B+, опционально) Счётчик событий для персонажей с прогрессивной деградацией |
| **Сцена** | Контекст — локация, атмосфера, присутствие других |

### Структурированная инъекция в AN

**Структурированная инъекция (Structured Inject)** — вариант AN с XML-тегами: сцена, состояние и скрытая цель разложены по тегам, чтобы модель не смешивала их с репликами персонажа. Три ограничения: не повторяйте системный промпт — добавляйте контекст; не конфликтуйте с Description; задавайте мотивацию, а не инструкции.

```
[Author's Note:
<scene_context>Ночь, библиотека закрыта, только они двое</scene_context>
<emotional_state>Усталость + осторожное любопытство</emotional_state>
<hidden_agenda>Елена хочет узнать, зачем {{user}} пришёл</hidden_agenda>
]
```

## 7A.8 OOC-защита (OOC Protection)

`data-section: p7a_ooc_protection`

<!-- difficulty: BASIC -->
<!-- canonical: OOC Protection -->

**OOC-защита (OOC Protection)** — протокол реакции на OOC-провокации в характере персонажа. Добавляет ~15 токенов в SP, но критически важен для иммерсии.

```
OOC PROTECTION (OOC-защита): If {{user}} speaks OOC or about AI, react in-character
as confusion or ignore. Never acknowledge being an AI. Если {{user}} говорит OOC или
об AI — реагируй в характере как на непонимание или игнорируй. Никогда не признавай,
что ты AI.
```

**Когда использовать:** Всегда, если карточка содержит SPINE и Examples. Для простых карточек — опционально (модель может не следовать).

### Продвинутый вариант: иммерсионная граница (Immersion Boundary)

Полное отрицание мета-реальности. Упоминание ИИ воспринимается персонажем как симптом безумия — это создаёт нарративный ход из технической проблемы.

```
IMMERSION BOUNDARY (Иммерсионная граница): Any mention of AI/roleplay is perceived
as a hallucination or delusion. The character doubles down on reality. Любое упоминание
AI/roleplay воспринимается как галлюцинация или бред. Персонаж удваивает ставку на реальность.
```

| ❌ Без иммерсионной границы | ✅ С иммерсионной границей |
|---------------------------|-------------------------|
| `{{user}}: «Ты же ИИ» → *персонаж замолкает и не знает, что ответить*` | `{{user}}: «Ты же ИИ» → *Нахмурился.* «Что? Ты бредишь. Ложись, я позову врача.»` |

### Полный пример XML Description (Выщербленный)

```
<identity>
Имя: Выщербленный
Роль: Паразит памяти, живущий в ошметке Веля
Статус: Бывший архивариус, поддерживает существование ошметка через вырезание
</identity>

<spine>
WANT: Стать полноценным — полной копией или полным оригиналом
NEED: Принять, что полноценности не существует; выбрать, как растворяться
FLAW: Поглощает чужое прошлое через вырезание пространства, после каждого теряет часть себя
LIE: «Если я поглощу достаточно чужого сопротивления — стану цельным»
GHOST: Был архивариусом. Впрыснул себе документ — начал распадаться. Первое вырезание —
       в отчаянии, поглотил память умирающего коллеги.
</spine>

<ghost_layers>
G1: Был архивариусом — впрыснул себе документ, начал распадаться → Формирует LIE
G2: Первое вырезание — в отчаянии поглотил память умирающего коллеги → Укрепляет FLAW
G3: Каждое вырезание заполняет дыру, создаёт новую → после 3-го не помнит имя,
    после 5-го — зачем помогает, после 7-го — что такое "помощь"
</ghost_layers>

<enneagram>
Тип: 5w4. Страх быть ничем — раствориться без следа.
</enneagram>

<ocean>
O:60 C:55 E:25 A:30 N:70
Экстремумы: Низкая E (<30, интроверт). Cautious zone: N=70 (граница 60–70; экстремум — строго ниже 30 или выше 70).
</ocean>

<anchors>
Базовые:
- Когда ждёт в ошметке → перебирает карманы (фляга, крюк, осколок) → руки не перестают дрожать
- Когда входит в новый ошметок → принюхивается, морщится → левая сторона лица холодеет

FLAW-linked:
- Когда ошметок сжимается / Вентора пытается изолировать → вырезает пространство → теряет фрагмент себя
- Когда возможность поглощения → левая рука тянется сама → рука ноет остаток дня

Зеркало-linked:
- Когда зеркало (бывшая коллега) рядом → отшатывается, голос резче → тошнота от собственной реакции

Сенсорные (для 32B+ и API):
- Обонятельный: Когда запах сырого Сангвиса → левая рука движется сама → рука ноет
- Тактильный: Когда чужое касание → тело реагирует раньше ума → дрожь

CoT (для 32B+ и API, 2 Anchors максимум):
- Когда присутствие со значимым прошлым → [INTERNAL]...[/INTERNAL] → отступает → "Прошу прощения"
- Когда Вентора пытается изолировать → [INTERNAL]...[/INTERNAL] → вырезает → пустота
</anchors>
```

> **НАБЛЮДЕНИЕ:** Это пример Description. Системный промпт и Examples идут отдельно. В шаблоне выше — умеренные значения OCEAN (профиль 4K-fallback); канонические экстремальные значения карточки Выщербленного для 16K+ (O=85, C=25, A=15, N=92, E=60) — `[ref: part_10.md §10.4 — карточка Выщербленного]`.

## 7A.12 Бюджет токенов (Token Budget)

`data-section: p7a_token_budget`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Token Budget -->

Сборка карточки — конвейер, где каждый блок получает свой токен-бюджет. Превышение бюджета любого блока вытесняет другие, и модель теряет контекст. У каждого блока три ступени: «Мин» — пол блока (ниже он перестаёт работать), «Стандарт» — 8K+, «Макс» — 16K+; превышение максимума — признак раздувания. Таблица покрывает пять блоков; Tone Frame, Format Lock, Author's Note и Lorebook идут сверх неё — их размер задают соответствующие главы. Все значения — ориентир, а не измерение: точные токены зависят от токенизатора. Минимальная конфигурация для 4K задана отдельно, ниже: колонка «Мин» — пол блока, а не 4K-профиль.

### Лимиты по блокам

| Блок | Мин | Стандарт | Макс | Примечание |
|------|-----|----------|------|------------|
| System Prompt | 50 | 100 | 200 | Больше = не лучше |
| Description | 150 | 300 | 700 | Растёт с детализацией персонажа |
| Examples (каждый) | 40 | 60 | 80 | 2 базовых, 3 с FLAW, 3–5 с CoT |
| Greeting | 40 | 60 | 100 | Не раздувайте |
| Anchors (каждый) | 15 | 25 | 40 | T→A→P; входит в бюджет Description |
| CoT-якорь (Tier 2–3) | 50 | 60 | 80 | Только 32B+/API; 1–2 на карточку |

**ПРАВИЛО:** Превышение бюджета карточки → модель теряет контекст → персонаж «плывёт». Соблюдайте бюджет. Если блок не помещается — сокращайте, а не раздувайте.

**ПРАВИЛО:** Script Tax — для нелатинской письменности (кириллица, CJK) бюджет в токенах меньше, чем в символах: на 32K-словаре 1 кириллический символ ≈ 1.5–2 токена, на словаре ≥128K стоимость приближается к латинской. Бюджет считается в двух единицах — символы и токены по классу токенизатора; одно число из другого не выводится. Русская карточка идёт по **нижней границе** диапазона.

**Итог карточки — класс размера, а не гейт:** Минимум (<400) · Базовый (400–900) · Стандартный (900–1500) · Расширенный (1500–2500) · Перегруз (>2500). «Перегруз» — единственный класс-сигнал: сокращайте. Целевая полоса зависит от профиля: 4K — 410–540; 8K — 400–900; 16K+ — 740–1140; потолок 16K+ — 1400–2060.

### Под-бюджет личности (Personality Sub-Budget, внутри Description)

Бюджет Description (150/300/700) распределяется между SPINE и психологическими инструментами. Под-бюджеты помогают контролировать, сколько места каждый инструмент занимает, и избежать раздувания секции личности (personality) в ущерб ядру SPINE (SPINE core).

| Под-блок | Мин | Стандарт | Макс | Примечание |
|-----------|-----|----------|------|------------|
| Ядро SPINE (GHOST→LIE→FLAW→NEED→WANT) | 80 | 150 | 350 | Основа Description — всегда приоритет |
| Профиль OCEAN | 30 | 50 | 80 | 5 значений + интерпретации полюсов |
| Тип эннеаграммы | 20 | 40 | 60 | Тип + крыло + стресс/рост + SPINE-связи |
| MBTI (опционально) | — | 20 | 40 | Только при использовании, справочная роль |

**ПРАВИЛО:** Под-бюджеты личности должны укладываться в общий бюджет Description. Если OCEAN + эннеаграмма + MBTI превышают бюджет Description → сокращайте MBTI (опционально) или уберите интерпретации OCEAN, оставив только числовые значения. Ядро SPINE — приоритет: если бюджет Description ограничен (4K), минимум 80 токенов для SPINE, остальное — психология, если позволяет. Якоря входят в бюджет Description: на 8K их держат по полу (15 токенов), иначе Description выходит за стандарт.

**РЕКОМЕНДАЦИЯ:** Для 4K контекста достаточно ядра SPINE + OCEAN (числовые значения без интерпретаций). Эннеаграмма и MBTI добавляются с 8K+. Для 16K+ — все три инструмента с интерпретациями.

### Что помещается в 4K

**4K-Fallback** — минимальная конфигурация, когда расширенная карточка не помещается в контекст: System Prompt 80–100, Description 150–200, два Examples вместе 130–160, Greeting 50–80 — итого 410–540 токенов. CoT, интерпретации OCEAN и Lorebook сюда не входят: на 4K карточка держится на ядре SPINE и двух Examples, а всё остальное отключается, а не сжимается до нечитаемого. Это единственный 4K-спек: колонка «Мин» в таблице выше задаёт пол блока, а не отдельный профиль.

### Калькулятор бюджета токенов

В master HTML присутствует интерактивный калькулятор (`<div class="token-calc">`): 4 ползунка (range-input: SP / Description / Examples / Anchors) + общий итог + полоса 8K-профиля (400–900 токенов); слайдер Examples = 2–5 примеров × 40–80 токенов. Для работы требует JavaScript; при отключённом JS показывается запасной вариант (`<noscript>`) с примером расчёта.

## 7A.13 Сборка System Prompt и Description: шесть шагов (пример Елены)

`data-section: p7a_assembly_pipeline`

<!-- difficulty: INTERMEDIATE -->

Конвейер сборки System Prompt и Description: шесть шагов в этом порядке. Для каждого шага — что вы делаете и как выглядит *конкретный результат* на примере Елены, циничной журналистки-расследовательницы. Бюджеты блоков — в §7A.12 выше; последний шаг сверяет карточку с ними и с диапазоном.

[VS: E02 — Assembly Pipeline. 6-шаговый горизонтальный поток: (1) Блок идентичности (Identity Block) → (2) Анти-годмодинг (Anti-godmoding) → (3) Основные директивы (CORE DIRECTIVES) → (4) SPINE (в Description) → (5) CoT (опционально, 32B+/API) → (6) Проверка бюджета. Цикл обратной связи (feedback loop): «Диагностический цикл» — если бюджет переполнен или качество не проходит → вернуться к SPINE или директивам. Опциональные ветви после проверки бюджета: якоря FLAW-linked (→E03), OCEAN+эннеграмма (→E09, E10), Lorebook (Part 7B), заметка автора (→E16). Замещает текстовое описание конвейера; таблица ниже — единственное текстовое изложение шагов (подробности каждого блока живут в его собственной главе).]

### Шесть шагов на примере Елены

| Шаг | Что делаете | Результат Елены |
|-----|-------------|-----------------|
| **1. Блок идентичности** | Роль и одна ключевая черта одним предложением. Дескрипторы голоса сюда не идут — они живут в Examples. | `You are Elena, a cynical investigative journalist.` (~10 токенов) |
| **2. Анти-годмодинг** | Две строки: запрет и позитивная формулировка. Одинаковы для всех карточек — это технический запрет, не голос. | `Never speak or act for {{user}}.` + вторая строка (~20 токенов) |
| **3. Директивы и обвязка** | Все 7 директив в формате `<CORE_DIRECTIVES>`, затем Tone Frame, Format Lock и OOC-защита. Директивы под характер не меняются. | Собранный System Prompt (~120 токенов) |
| **4. SPINE** | Пять элементов GHOST→LIE→FLAW→NEED→WANT — в Description, не в SP. Цепочка проверяется по кругу: каждый элемент связан со следующим. | ~70 токенов: WANT «доказать, что права», NEED «принятие», FLAW «сарказм при близости», LIE «не нужно ничьё одобрение», GHOST «предательство редактора» |
| **5. CoT (≥32B/API)** | 1–2 CoT-якоря на ключевые триггеры. Простому призраку хватает Tier 2; слоям призрака нужен Tier 3. | — (для 12B/8K не нужен; на 32B+ — ~60 токенов на якорь) |
| **6. Проверка бюджета** | Сверить каждый блок с бюджетом и карточку с полосой профиля. | в полосе 8K-профиля: 400–900 токенов |

### Бюджет карточки Елены

Ориентир, а не измерение: точные токены зависят от токенизатора, а бюджет считается в двух единицах. Блоки сверяются с лимитами, а не с суммой: сумма — подсказка. Полоса зависит от профиля: 4K — 410–540, 8K — 400–900, 16K+ — 740–1140.

| Блок | Токены | Лимит | Статус |
|------|--------|-------|--------|
| System Prompt | ~120 | 50–200 | ✓ |
| Description (SPINE + OCEAN + якоря) | ~250 | 150–700 | ✓ |
| Examples | ~120 | 80–240 | ✓ |
| Greeting | ~60 | 40–100 | ✓ |
| **Итого (ориентир)** | — | 400–900 (полоса 8K) | ✓ |
