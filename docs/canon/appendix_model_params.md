# Appendix E: Модель, контекст и параметры генерации

## E.1 Модель, контекст и параметры генерации

`data-section: appendix_model_params`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: model capabilities + context profiles + sampling + Script Tax + SP language + API wrappers + frontend EVENT compatibility -->

Приложение отвечает на три вопроса, которые читатель задаёт **один раз — до сборки карточки**, и которые больше не живут в линейном потоке:

1. **Какую модель взять** — что умеют 12B–14B, 32B+ и API-модели.
2. **Сколько контекста ей нужно** — профили 4K / 8K / 16K+ и 4K-Fallback.
3. **Какие параметры выставить** — сэмплирование, Presence Penalty, интерфейс запуска.

Здесь — только модель, рантайм и параметры сборки.

### Возможности моделей (12B–14B / 32B+ / API)

Эта таблица объединяет всю зависимость методов от размера модели. Ссылки на неё заменяют отдельные заметки `[Модель: …]` в тексте гайда: упоминание модели в Part 6/7A означает «строка этой таблицы».

| Возможность | 12B–14B | 32B+ | API (Claude/GPT) |
|-------------|---------|------|------------------|
| Эффективность CoT | Базовая: Tier 0–1 | Полная: Tier 0–3 | Полная: Tier 0–3 |
| Рабочий уровень CoT | Tier 0 (`[ref: part_06.md §6.2 — уровни CoT]`) | Tier 1–2 | Tier 2–3 |
| Следование SPINE | Умеренное | Высокое | Высокое |
| Следование основным директивам | ~60–80% | ~85–95% | ~90–98% |
| Директива №6 (Consequence Driven) | Ограниченный эффект — недостаточная глубина рассуждений | Значительный эффект | Полный эффект |
| Директива №7 (Pre-Generation Filter) | ~40–60% соблюдения — часто игнорируется | ~85–95% соблюдения | ~90–98% соблюдения |
| Размещение голоса | Examples + Greeting — **никогда в Description** (`[ref: part_03.md §3.1 — изоляция голоса]`) | Examples + Greeting — никогда в Description | Examples + Greeting + AN — никогда в Description |
| XML-теги | ⚠️ нестабильны — структурированная инъекция ограничена | ✓ стабильны | ✓ стабильны |
| Anti-godmoding | 2 строки (запрет + позитив) | 2 строки | 1 строка |
| Язык SP | Английский для словаря <64K¹; язык карточки допустим для ≥128K | Язык карточки предпочтителен | Язык карточки предпочтителен |
| Следование инструкциям на английском | Исторически выше (доминирование английского в обучении); разрыв сужается на словаре ≥128K | Стабильно в обоих языках | Стабильно в обоих языках |
| Размер словаря | 32K (ранние 12B); 128K (актуальные 12B–14B: Gemma 3, Qwen 2.5, Mistral Nemo) | 32K–128K (зависит от поколения) | 100K+ (Claude 200K, GPT-4 128K, Gemini 1M+) |
| Налог на письменность (Script Tax, нелатиница) | Высокий на 32K-словаре (кириллица ≈1.5–2× латиницы; CJK ≈1–2×) | Средний на 32K; низкий на ≥128K | Низкий (словарь 200K+ покрывает большинство письменностей) |

¹ Язык SP: многоуровневое правило; пороги и обоснование — подраздел «Язык системного промпта» ниже.

**НАБЛЮДЕНИЕ:** Процентные оценки возможностей (~60–80% / ~85–95% / ~90–98%) — эмпирические наблюдения, а не нормативные пороги: они ориентировочны и зависят от промпта, фронтенда и поколения модели. Правила и рекомендации гайд задаёт в профильных разделах, а не этой таблицей.

#### Ключевые следствия для сборки карточки

- **12B–14B:** только Tier 0–1 CoT, упрощённая SPINE, ожидать ~60–80% следования основным директивам. Язык SP — по порогам модели (см. «Язык системного промпта»). Script Tax на 32K-словаре увеличивает расход токенов для нелатинских письменностей в 1.5–2 раза.
- **32B+:** полный Tier 0–3 CoT, высокое следование SPINE, ~85–95% следования директивам. Фильтр предгенерации работает надёжно.
- **API-модели:** максимальная стабильность, ~90–98% следования. Структурированная инъекция (XML) рекомендуется для сложных персонажей.

### Сколько контекста: 4K / 8K / 16K+

Бюджет блоков по профилям контекста: Мин = 4K · Стандарт = 8K+ · Макс = 16K+. Ниже — минимальная конфигурация для моделей с ограниченным контекстом.

**4K-Fallback** — минимальная конфигурация для моделей с контекстом 4K токенов. Используется, когда расширенная карточка не помещается в контекстное окно.

#### Токен-лимиты 4K (конфигурация развёртывания в пределах лимитов §7A.12)

| Блок | Полный (§7A.12) | 4K-Fallback |
|------|--------|-------------|
| System Prompt | 50–200 | 80–100 |
| Description | 150–700 | 150–200 |
| Examples | 80–400 (2–5 × 40–80) | 130–160 (2 × 65–80) |
| Greeting | 40–100 | 50–80 |
| **Итого** | 850–1450 | ~430–580 |

#### Минимальный SP (4K)

```
You are {{char}}. Never speak or act for {{user}}.
Role: {{role}}
Key trait: {{one_extreme_ocean_pole}}
```

#### Минимальный Description (4K)

```
{{name}} — {{role}}.
{{one_sentence_summary}}

Anchors:
- {{trigger}} → {{action}} → {{price}}
- {{trigger}} → {{action}} → {{price}}
- {{trigger}} → {{action}} → {{price}}
```

**ПРАВИЛО:** Якоря в 4K-fallback размещаются в Description (как `<anchors>`-тег или список), поскольку фронтенд не имеет отдельного поля — концепция и полное правило размещения якорей. При 8K+ и API используйте `<anchors>`-тег внутри Description для структурирования.

**РЕКОМЕНДАЦИЯ:** 4K-Fallback — для 12B моделей. Если контекст позволяет 8K+, используйте стандартный профиль.

### Параметры генерации (сэмплирование)

Параметры генерации влияют на разнообразие и предсказуемость ответов модели. Для карточек персонажей рекомендации отличаются от обычного чата — голос персонажа требует повторяемых паттернов.

[VS: E17 — Sampling Parameters. Сравнительная 3-колоночная таблица: 12B-14B (наиболее ограниченный) / 32B+ (рекомендуемый) / API (максимальная гибкость). По строкам: Temperature, Top P, Min P, RepPen, Top K, Presence Penalty (везде `0.0 ⚠️`). Дополнительно — чеклист по типу модели: размещение голоса, стабильность XML, уровень CoT, Anti-godmoding. Значения — SHARED_REFERENCE: этот подраздел Приложения E — канонический владелец (таблицы «Базовые параметры» + «Модель-специфичные рекомендации»), E17 — единственная визуальная презентация (колонка 32B+ = колонка «32B+ / API» канона; средний ярус «12B–32B» — заявленное отсутствие в визуале: значения живут только в канонической таблице); паритет фиксирует `scripts/audit_sampling_parity.py`.]

#### Базовые параметры

| Параметр | 12B | 12B–32B | 32B+ / API | Примечание |
|----------|-----|---------|------------|------------|
| **Temperature** | 0.6–0.8 | 0.7–0.9 | 0.7–1.0 | Ниже = предсказуемее, выше = разнообразнее |
| **Top P** | 0.9 | 0.9–0.95 | 0.9–0.95 | Nucleus sampling, обычно не трогать |
| **Min P** | 0.05 | 0.05–0.1 | 0.05–0.1 | Отсечение маловероятных токенов |
| **RepPen** | 1.0–1.05 | 1.05–1.10 | 1.05–1.10 | Никогда > 1.10 — убьёт голос (AP-5) |
| **Top K** | 40 | 40–80 | 40–100 | Ограничение выбора токенов |
| **Presence Penalty** | **0.0** | **0.0** | **0.0** | Обязательно 0 — иначе голос дрейфует (AP-7) |

**ПРАВИЛО:** Presence Penalty = 0.0 для ВСЕХ карточек персонажей. Это не рекомендация, а правило. Любое значение > 0 заставляет модель избегать повторения тем — включая характерные паттерны речи персонажа.

**ПРАВИЛО:** Ollama и LM Studio имеют захардкоженный `presence_penalty = 0.7`. Это ломает карточки (AP-7). Рекомендуемые интерфейсы, позволяющие PP = 0.0: **KoboldCPP**, **TabbyAPI**, **vLLM**.

#### Модель-специфичные рекомендации

| Модель | Temperature | RepPen | Особенности |
|--------|-------------|--------|-------------|
| **12B (4K)** | 0.6–0.7 | 1.0 | Низкий контекст — используйте 4K-Fallback (см. выше) |
| **32B+** | 0.7–0.9 | 1.05 | Хорошо держит голос при достаточных Examples |
| **Claude API** | 0.8–1.0 | — | RepPen не нужен, используйте `<claude_info>` (см. ниже) |
| **GPT API** | 0.8–1.0 | — | Используйте `[SYSTEM NOTE]` для инструкций (см. ниже) |

**РЕКОМЕНДАЦИЯ:** На API-моделях заметка автора (AN) может содержать краткие голосовые напоминания (~10 токенов), т.к. API-модели лучше следуют инструкциям. На 12B — нет, влияние AN на голос пренебрежимо мало (~2%).

### Налог на письменность (Script Tax)

**ПРАВИЛО:** Script Tax (налог на письменность) — для нелатинских письменностей (Cyrillic, CJK) фактический бюджет токенов уменьшается: 1 кириллический символ ≈ 1.5–2 токена на 12B-моделях с 32K словарём, ≈ 1 токен на ≥128K словаре и API. Учитывайте это при расчёте бюджета токенов (Token Budget) для карточек на русском, японском, корейском и других языках с нелатинской графикой — бюджет в «символах» и «токенах» расходится. Порог: ≥128K словаря → Script Tax несущественен.

Практическое следствие для бюджета: русская карточка на 32K-словаре идёт по **нижней границе** диапазона бюджета; на ≥128K-словаре и API — Script Tax не меняет расчёт.

### Язык системного промпта

Правило языка (включая RP-контент — всегда на языке карточки) и его пороги — ниже.

**ПРАВИЛО:** Язык SP (Identity + Anti-godmoding + CORE DIRECTIVES + Tone Frame + Format Lock) — многоуровневый по модели:

- **12B со словарём <64K** (ранние Llama 2, Qwen 1.x, ранний Mistral): английский — исторически стабильнее (смещение обучающей выборки ранних моделей).
- **12B–14B актуальных поколений со словарём ≥128K** (Gemma 3 12B, Mistral Nemo, Qwen 2.5 14B): английский оптимален, но язык карточки допустим — разрыв несущественен.
- **32B+ и API:** язык карточки предпочтителен — модель полностью мультиязычна, единый язык SP и RP улучшает консистентность (нет переключения контекста между инструкцией и контентом).

Пороговое правило: если модель имеет ≥128K словаря и нативную поддержку языка карточки — используйте язык карточки для всего SP. Если нет — используйте английский для SP, язык карточки для RP-контента.

### API-обёртки: `<claude_info>` и `[SYSTEM NOTE]`

API-модели (Claude, GPT-4) поддерживают специфичные форматы инструкций, которые недоступны или работают иначе на open-source моделях. Эти блоки размещаются:

- В начале Description (рекомендуется для Claude);
- Как отдельные инъекционные элементы (GPT System Message);
- В First Message (для некоторых конфигураций).

#### Claude: `<claude_info>`

```
<claude_info>
{{char}} — {{role}}.

Ключевые характеристики:
- {{trait_1}}
- {{trait_2}}

Поведение:
{{behavior_guidelines}}

Ограничения:
- Не нарушай характер
- Не говори за {{user}}
</claude_info>
```

#### GPT: `[SYSTEM NOTE]`

```
[SYSTEM NOTE: {{char}} — {{role}}.
Ключевые характеристики: {{traits}}.
Поведение: {{behavior}}.
Ограничения: не нарушай характер, не говори за {{user}}.]
```

### Совместимость `EVENT:` по фронтендам

Синтаксис `EVENT:` для range-триггеров Lorebook поддерживается не всеми фронтендами.

| Фронтенд | Поддержка | Примечание |
|----------|-----------|------------|
| SillyTavern | Полная | EVENT:, SECONDARY_KEYS, selective activation |
| Soul of Waifu | Есть аналоги | Расширенные возможности |
| KoboldAI | Частичная | Использовать conditionals в entry content, KEYWORD без EVENT: |
| Oobabooga | Нет | Использовать Lorebook (World Info) или встройте триггеры в Description/AN |
| Faraday.dev / Agnai | Ограниченная | Проверяйте документацию конкретного фронтенда |

Если фронтенд не поддерживает `EVENT:` — триггеры задаются через conditionals в `content` записи или через Description/AN карточки.

Модель, контекст и параметры — один раз на проект, а не на карточку. Выберите строку таблицы возможностей, профиль контекста и параметры сэмплирования; дальше собирайте карточку и проверяйте её по бюджету блоков.
