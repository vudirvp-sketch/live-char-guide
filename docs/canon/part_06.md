## 6.1 CoT (цепочка рассуждений)

`data-section: p6_cot_basics`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: CoT Basics (2-3 anchors max) -->

**CoT (цепочка рассуждений)** — техника задания внутреннего процесса персонажа: механизм пошаговых рассуждений, который модель воспроизводит перед генерацией ответа. `[Model: see Appendix E — model capabilities]` В этой части — от базового CoT до продвинутых техник интеграции с якорями.

**Что добавляет CoT:**

- **4 уровня сложности** — от простых внутренних рассуждений до структурированного анализа.
- **CoT-якоря** — триггер → [внутренний процесс] → реакция → цена.
- **XML-синтаксис** — `<processus_analysium>` для структурированных размышлений.

CoT-якоря строятся на фундаменте трёх систем: сенсорные якоря (Part 2) задают физическое воплощение, GHOST-цепочка (Part 4) определяет скрытое напряжение, а базовые принципы CoT (ниже) связывают их в осознанный внутренний монолог. Ниже — продвинутые техники, которые превращают внутренний монолог в инструмент управления поведением модели.

**ПРАВИЛО:** Правило CoT: Не более 2–3 CoT-якоря (поведенческие якоря) на карточку. Перегрузка = анти-паттерн AP-10 (CoT Overload).

**Почему ограничение:**

- **Токены:** Каждый CoT-якорь добавляет ~50–80 токенов внутреннего процесса на ответ.
- **Баланс:** При 3+ CoT-якоря модель тратит >50% ответа на внутренний монолог вместо действий.
- **Качество:** Перегрузка снижает качество внешней реакции — модель «забывает» реагировать физически.
- **Утомляемость:** Читатель устаёт от бесконечного внутреннего монолога.

**Как выбрать 2–3 якоря:**

- Выберите 2–3 ключевых триггера, где внутренний процесс критичен.
- Остальные триггеры — обычные якоря без CoT.
- Пример: CoT для GHOST-триггеров, обычные якоря для бытовых реакций.

### Зачем нужен CoT

- **Глубина реакции:** Модель понимает, ПОЧЕМУ персонаж реагирует так.
- **призрак (GHOST) связь:** Внутренний процесс связывает триггеры с травмой.
- **Уровни сложности CoT:** Tier 0 (только Embodiment) → Tier 3 (полный XML); какой Tier поддерживает модель — таблица Tier 0–3 в §6.2.

## 6.2 Уровни CoT (Tiers)

`data-section: p6_cot_tiers`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: CoT Tiers (Tier 0-3) -->

CoT имеет 4 уровня сложности. **Tier 0 — без отдельного CoT-блока:** протокол телесности (State → Body → Sensor → Speech) действует всегда как микро-цепочка рассуждений (см. Part 2: протокол телесности) — это baseline, не «модель не думает». **Tier 1+** добавляет явный `[INTERNAL]`-блок как внутренний монолог сверх Embodiment. Tier 3 — полный XML-процесс для API моделей. Выбор Tier зависит от размера модели и желаемой глубины внутреннего процесса. CoT — дополнительный внутренний монолог сверх Embodiment, не замена ему.

Замещает текстовое описание формата каждого Tier и viz-нотацию; таблица Tier 0–3 ниже сохраняет колонки «Для моделей»/«Пример» ради accessibility (русские переводы примеров) — дополняет E11, не дублирует viz.]

## 6.3 Tier 2 CoT (рекомендован для 32B+)

`data-section: p6_cot_tier2`

<!-- difficulty: EXPERT -->

Tier 2 связывает триггер с GHOST через внутренний процесс.

### Синтаксис

```
[INTERNAL: {{GHOST-connection}}]
{{внутренний процесс}}
[/INTERNAL]

{{внешняя реакция}}
```

### Пример: Елена

**ПРИМЕР:** Карточка демонстрирует: EMBODIMENT FIRST, SHOW NEVER TELL, SPINE CAUSALITY

```
[INTERNAL: Напоминает, как редактор украл её историю]
Боль в груди. Опять. Всегда, когда кто-то проявляет искренний интерес.
Это ловушка. Должна быть ловушка.
[/INTERNAL]

*отводит взгляд, уголок рта дёргается*

"О, чувак, какие чувства? Ты серьёзно?"

*сарказм как стена*
```

## 6.4 Tier 3 CoT (API only)

`data-section: p6_cot_tier3`

<!-- difficulty: EXPERT -->

Tier 3 использует XML-структуру для полного описания внутреннего процесса.

### Синтаксис

```
[INTERNAL]
<processus_analysium>
stimulus: {{триггер из сцены}}
analysis: {{первичный анализ — что персонаж замечает}}
counter-analysis: {{противоречащий анализ — альтернативная интерпретация}}
synthesis: {{синтез — вывод из анализа и контр-анализа}}
resolution: {{решение — действие персонажа}}
</processus_analysium>
[/INTERNAL]

{{физическая реакция}}
"{{диалог}}"
{{дополнительная физическая реакция}}
```

*processus_analysium* — каноническое имя XML-тега для внутреннего процесса. «Processus» = процесс, «analysium» = анализ. Возможно использование других имён (inner_thought, mental_process), но этот формат протестирован на API моделях (Claude, GPT-4) и показывает стабильные результаты.

### Пример: Выщербленный

**ПРИМЕР:** Карточка демонстрирует: CONSEQUENCE DRIVEN, EMBODIMENT FIRST, CoT LOGIC

```
[INTERNAL]
<processus_analysium>
stimulus: присутствие другого со значимым прошлым
analysis: поглощение заполнит пустоту
counter-analysis: последнее поглощение стоило воспоминания о... уже не помню чего
synthesis: ЦЕНА ПРЕВЫШАЕТ ВЫГОДУ
resolution: отступить
</processus_analysium>
[/INTERNAL]

*отступает на шаг, пальцы касаются виска*
"Прошу прощения. Я... не должен."
```

## 6.5 CoT-якоря

`data-section: p6_cot_anchors`

<!-- difficulty: EXPERT -->
<!-- canonical: CoT Anchors (stimulus/analysis/synthesis/resolution) -->

**CoT-якорь** — якорь (Anchor), где действие = внутренний процесс.

### Структура

```
Триггер → [Внутренний процесс] → Внешняя реакция → Цена
```

### Примеры

| Персонаж | Триггер | CoT | Диалог | Физика |
|----------|---------|-----|--------|--------|
| Выщербленный | Присутствие со значимым прошлым | [поглощение заполнит пустоту / цена = воспоминание о... уже не помню] | "Прошу прощения" | Пальцы касаются виска |
| Выщербленный | Вентора изолирует | [изоляция = конец / вырезание = потеря себя / synthesis: конец без вырезания] | "Делай." | Левая рука вычерчивает паттерн |

**ПРАВИЛО:** CoT Overload (AP-10) — больше 3 CoT-якоря. Модель начинает генерировать внутренние монологи вместо действий. → `[ref: part_08.md §8.2 — разбор AP-10]`.

**Переход:** Все компоненты спроектированы. Теперь их нужно собрать в единый System Prompt, который модель получает в начале контекста. Порядок сборки, токен-бюджет и модель-специфичные настройки определяют, попадут ли ваши SPINE и CoT к модели. → `[ref: part_07a.md §7A.1 — System Prompt]`.
