## 0.1 Как читать этот гайд

`data-section: p0_how_to_read`

<!-- difficulty: BASIC -->

Гайд — единый линейный поток от Part 1 до Part 10. Каждый Part — отдельный модуль, который строит на предыдущем. Читать последовательно; значимые нарративные переходы между Parts обозначены меткой **Переход (Bridge)** (только 2 в гайде: Part 6→7A «от психологии к сборке», Part 9→10 «от диагностики к примерам»).

**Что такое Part:** концептуальный модуль. Карта модулей:

| Part | Тема | Что даёт |
|------|------|----------|
| Part 1 | Основы (Foundations) | Зачем системный подход, базовые блоки, 3 ключевых правила, чек-лист перед сборкой |
| Part 2 | Якоря (Anchors) | Поведенческие якоря: Trigger → Action → Price |
| Part 3 | Голос (Voice) | Изоляция голоса, Examples, мульти-персонажность |
| Part 4 | SPINE | Психологический каркас: GHOST → LIE → FLAW → NEED → WANT |
| Part 5 | Психология | OCEAN, эннеаграмма, MBTI — валидация SPINE |
| Part 6 | CoT | Цепочка рассуждений (Chain of Thought) для внутренних конфликтов в моменте |
| Part 7A | System Prompt | Сборка SP, основные директивы (CORE DIRECTIVES), XML-теги, бюджет токенов |
| Part 7B | Lorebook | База знаний с триггерами |
| Part 8 | Анти-паттерны | 15 типовых ошибок и их фиксы |
| Part 9 | Диагностика | Дерево решений, тестовые сценарии, валидация перед деплоем |
| Part 10 | Примеры | 4 готовые карточки разной сложности |

**Что такое VS-EMBED:** визуализация, замещающая длинное текстовое описание. В canon-файлах помечена маркером `[VS: E0X — описание. Что замещает.]`. В master HTML рендерится как `<div class="vs-embed" data-vs-element="E0X">`. 18 VS-элементов (E01–E18) в `visual-system/elements/`. Принцип `viz > dry text` — визуализация замещает, а не дублирует текст.

**Нотация `[ref: ...]`:** навигационный указатель между canon-файлами. Форматы: `[ref: part_XX.md §X.Y — Topic]` (между файлами) или `[ref: §X.Y]` (внутри файла). Используется только для навигации между Parts (указание, где находится конкретный блок), не для повторного объяснения уже введённых концепций.

**Метки callouts** (русские — проза гайда; тело callouts — на русском):

- `**ПРАВИЛО:**` — каноническое правило (нарушение = регрессия качества).
- `**РЕКОМЕНДАЦИЯ:**` — мягкая рекомендация.
- `**ПРИМЕР:**` — пример выполнения.
- `**ИЛЛЮСТРАЦИЯ:**` — визуальная демонстрация (diff-view, мульти-персонажная сцена).
- `**ШАБЛОН:**` — шаблон для копирования.
- `**Переход:**` — нарративный переход между Parts (только 2 в гайде).
- `**Синтез:**` — 1–2 предложения итога в конце Part.
- `**Ссылка:**` — навигационный указатель на секцию в другом Part.
- `**Демонстрирует:**` — список принципов, которые карточка демонстрирует.
- `**Примечание:**` — уточняющий комментарий.

Английский остаётся только внутри исполняемых промпт-контейнеров (где гайд предписывает английский), идентификаторов и имён собственных — с русским пояснением рядом.

## 0.2 TL;DR / Быстрый старт

`data-section: p0_tldr_quick_start`

<!-- difficulty: BASIC -->

Минимальная карточка за 30 минут. Карточка = 4 блока: System Prompt (SP), Description, Examples, Greeting.

**6 шагов сборки:**

1. **System Prompt (SP):** «You are [имя], [роль]. Never speak or act for {{user}}.» + Tone Frame + Format Lock. ~50 токенов.
2. **Description:** `<identity>` + `<spine>` (WANT/NEED/FLAW/LIE/GHOST — 1 строка на каждый элемент). ~150 токенов.
3. **Examples (2–3 блока `<START>`):** каждый 80–120 токенов, демонстрирует голос + минимум один embodiment (физическая реакция). Голос задаётся ТОЛЬКО здесь.
4. **Greeting:** 50–100 токенов, 4 шага (сенсорный якорь → тело FLAW → реплика → крючок).
5. **Якоря (Anchors, 3–5):** Trigger → Action → Price (Price = наблюдаемый физический маркер в той же сцене).
6. **Проверка перед деплоем:** 5 быстрых проверок (PP=0, Voice в Examples, Price в Anchors, Format Lock, Anti-godmoding).

Гайд строится на трёх обязательных принципах, которые подробно разбираются в Part 1: якорь (Anchor) = T→A→P (без Price якорь = инструкция без паттерна), голос задаётся только в Examples и Greeting (Voice в Description = потеря токенов), психология размещается только в Description (никогда в System Prompt).

**С чего начать:** если вы делаете карточку впервые — начните с Елены, скопируйте структуру, замените содержимое. Не пытайтесь сразу строить Омнис-Зета (~1800 токенов, слои призрака, CoT, Lorebook) — это ведёт к перегрузке и утечке голоса.

**Ссылка:** Чек-лист перед сборкой (6 вопросов перед стартом) → `[ref: part_01.md §1.8 — чек-лист перед сборкой]`. Валидация перед деплоем (5+14 проверок) → `[ref: part_09.md §9.11]`. Готовые карточки → `[ref: part_10.md §10.1]`.
