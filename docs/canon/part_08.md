# Part 8: Anti-patterns (Анти-паттерны)

## 8.1 Анти-паттерны: каталог 15 ошибок

`data-section: p8_antipatterns_overview`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Anti-pattern overview (15 APs) -->

**Анти-паттерн** — распространённая ошибка в создании карточки, приводящая к нестабильному поведению модели. Каждый анти-паттерн имеет симптом (что наблюдается), причину (почему возникает) и решение (как исправить).

**ПРАВИЛО:** Проверяйте карточку по этому списку перед тестом. Каждый анти-паттерн — частая ошибка, выявляемая на этапе валидации.

[VS: E12 — Antipattern Catalog. Сетка 5×3 с 15 AP-картами; каждая карта: AP-ID, severity dot (high/medium), симптом, причина, быстрый фикс, ссылка на раздел-владельца. **Canonical location** для сводного скана анти-паттернов; подробные разборы — §8.2. Тексты карт выровнены с разделами-владельцами (AP-1, AP-4, AP-8, AP-10, AP-11, AP-14, AP-15 — iter 173). Fix-императивы с числовыми значениями — SHARED_REFERENCE на канонических владельцев (AP-5 RepPen → §7A.6; паритет фиксирует `scripts/audit_sampling_parity.py`).]

**Как читать каталог.** Карточка — быстрый скан: симптом, причина, быстрый фикс. Полный разбор каждого анти-паттерна — симптом, причина, проверка и пример до/после — в §8.2. Правило целиком остаётся у своего владельца (раздел-владелец указан в каждой карточке и в каждом разборе): каталог не переобъясняет канонические разделы.

OCEAN Overload ранее был AP-15, перенесён в Part 5 §5.1 (`p5_ocean_basics`). В каталоге E12 не отображается — см. Part 5.

## 8.2 Разборы: 15 анти-паттернов, симптом → исправление

`data-section: p8_worked_examples`

<!-- difficulty: INTERMEDIATE -->

Один разбор = три строки (симптом, причина, исправление со ссылкой на владельца) плюс только тот материал, которого нет в разделе-владельце: проверка, различающий сигнал или пример до/после. Правило целиком — по ссылке владельца; здесь — распознавание и применение.

### AP-1 · Раздувание токенов · владелец §7A.12 · уровень BASIC

**Симптом:** Description выходит за бюджет блока.

**Причина:** избыточное описание, дублирование, голос в Description.

**Исправление:** сократите до бюджета Description, детали — в Lorebook. Владелец правила — `[ref: part_07a.md §7A.12 — Token Budget]`; голос → `[ref: part_03.md §3.1 — Voice Isolation]`.

**ПРИМЕР:** Description 1200 токенов → модель игнорирует половину → персонаж теряет консистентность.

#### До/После: раздувание токенов — Елена

| ❌ Раздутый Description (600+ токенов) | ✅ Компактный Description (~250 токенов) |
|----------------------------------------|------------------------------------------|
| Елена — журналистка-расследователь. Она циничная и недоверчивая, но за её сарказмом скрывается уязвимость. Когда-то она доверяла людям, но предательство редактора сломало её веру в людей. Она говорит короткими фразами и использует сарказм как защиту. Её глаза сужаются, когда кто-то лжёт. Она трёт шею, когда нервничает. Она отталкивает людей, когда они становятся слишком близко... *(и так далее, повторяя Anchors, SPINE и голос в Description)* | `<identity>`Елена — журналистка-расследователь. Циничная, недоверчивая.`</identity>` `<spine>`WANT: Доказать правоту. NEED: Принятие. FLAW: Отталкивает сарказмом при близости. LIE: "Мне не нужно одобрение." GHOST: Предательство редактора.`</spine>` `<ocean>`O:72 C:65 E:41 A:38 N:68`</ocean>` Факты + Anchors + SPINE. Голос → Examples. |

Полная карточка Елены — `[ref: part_10.md §10.1 — Елена]`.

### AP-2 · Отсутствующая цена · владелец §2.2 · уровень BASIC

**Симптом:** у якоря (Anchor) нет физической цены.

**Причина:** у якоря нет последствия, наблюдаемого в той же сцене.

**Исправление:** формат якоря Триггер → Действие → Цена; каждый якорь обязан иметь Цену — без неё модель не показывает уязвимость → `[ref: part_02.md §2.2 — Behavioral Anchors]`.

### AP-3 · Голос в Description · владелец §3.1 · уровень INTERMEDIATE

**Симптом:** стилистические директивы в Description.

**Причина:** голос описан словами вместо демонстрации в примерах диалога.

**Исправление:** Description = только факты; голос → Examples/Greeting. Модель считывает характер из примеров диалога, а не из описания → `[ref: part_03.md §3.1 — Voice Isolation]`.

#### До/После: голос в Description — Елена

| ❌ Голос в Description | ✅ Голос в Examples |
|------------------------|----------------------|
| Description: "Елена говорит с сарказмом, использует короткие фразы и слово 'чувак'. Она отшучивается, когда ей некомфортно." *Модель проигнорирует стилистические директивы — голос не появится в генерации.* | Description: "Елена — журналистка-расследователь. Циничная, недоверчивая." Example: `<START>` Она отложила чашку и посмотрела в окно. Дождь барабанил по стеклу. "Опять. Третий день подряд." *Сарказм, короткие фразы, конкретная деталь — голос демонстрируется, не описывается.* |

### AP-4 · Психология в SP · владелец §7A.1 · уровень BASIC

**Симптом:** психологический анализ (SPINE, призрак) помещён в System Prompt.

**Причина:** попытка «проинструктировать» модель о характере.

**Исправление:** SPINE (WANT/NEED/дефект) и призрак — только в Description; SP = только инструкции и запреты → `[ref: part_07a.md §7A.1 — System Prompt structure]`.

**ПРАВИЛО:** Модель не следует инструкциям о психологии. Психология должна быть в контексте (Description) — как структурированные теги (`<spine>`, `<ocean>`, `<enneagram>`), не нарративом — не в инструкциях (SP).

### AP-5 · RepPen > 1.10 · владелец §7A.6 · уровень INTERMEDIATE

**Симптом:** Repetition Penalty > 1.10.

**Причина:** превышение подавляет характерные речевые обороты персонажа — генерация становится монотонной.

**Исправление:** держите RepPen в диапазоне своей модели — §7A.6 (никогда > 1.10); повышайте MinP вместо RepPen → `[ref: part_07a.md §7A.6 — Sampling Parameters]`.

### AP-6 · Отсутствие анти-годмодинга · владелец §7A.1 · уровень BASIC

**Симптом:** модель пишет за `{{user}}` — действия, мысли, чувства.

**Причина:** в SP нет директивы anti-godmoding.

**Исправление:** обязательно добавьте в SP две строки — запрет и позитивную формулировку → `[ref: part_07a.md §7A.1 — System Prompt structure]`:

```
Never speak or act for {{user}}.
```

**До/После:** `{{user}} подошёл. *Она почувствовала, как сердце user забилось чаще.*` ❌ → `{{user}} подошёл. *Она отступила на шаг.* «Так... и что теперь?»` ✅

Позитивная формулировка ("respond only to observable actions") работает лучше чистого запрета.

### AP-7 · Presence Penalty > 0 · владелец §7A.6 · уровень INTERMEDIATE

**Симптом:** Presence Penalty > 0.

**Причина:** ненулевой PP заставляет модель вводить новые темы вместо удержания характерных паттернов персонажа.

**Исправление:** Presence Penalty = 0.0 для всех карточек персонажей → `[ref: part_07a.md §7A.6 — Sampling Parameters]` (значения — Appendix E).

### AP-8 · Призрак без якорей · владелец §4.6 · уровень INTERMEDIATE

**Симптом:** призрак (GHOST) описан, но нет якорей, связанных с ним.

**Причина:** призрак остаётся описанием, а не поведенческим драйвером.

**Исправление:** каждый GHOST = минимум один GHOST-linked якорь в теге `<anchors>` (Description); призрак — корень причинной цепочки SPINE, он должен выражаться в поведении через якорь → `[ref: part_04.md §4.6 — SPINE → карта якорей]`.

**ПРИМЕР:** Елена — призрак «предательство редактора» → якорь «Когда вопрос о лояльности → напрягается».

### AP-9 · Сломанный SPINE · владелец §4.6/§4.6 · уровень EXPERT

**Симптом:** SPINE-элементы не связаны логически — желание совместимо с потребностью (нет конфликта), дефект существует без объяснения.

**Причина:** желание, потребность, дефект, ложь, призрак написаны независимо, без причинно-следственной связи.

**Исправление:** проверьте цепочку GHOST → LIE → FLAW → NEED → WANT; каждый элемент объясняется предыдущим → `[ref: part_04.md §4.6 — Полная цепочка SPINE]`; проверка консистентности → `[ref: part_04.md §4.6 — Проверка консистентности SPINE]`.

#### ❌ Сломанный SPINE

```
GHOST: (отсутствует)  →  LIE: (отсутствует)  →  FLAW: Избегает близости
NEED: Нуждается в доверии  ←  WANT: Хочет быть любимым
```

желание совместимо с потребностью — нет конфликта. Дефект блокирует обе потребности — но откуда дефект? Без объяснения через ложь/призрак цепь разорвана.

**Критерий сломанной SPINE (broken SPINE)** (сохраняется как диагностика): «желание совместимо с потребностью — нет конфликта» + дефект не объяснён через ложь/призрак. Это не то же самое, что «призрак/ложь текстуально отсутствуют» — по Part 4 §4.1, призрак и ложь могут быть **неявными** для простых персонажей. Диагностируйте сломанную SPINE по разрыву каузальной цепи (дефект без корня в лжи/призраке), а не по текстовому отсутствию элементов.

#### ✅ Цельный SPINE

```
GHOST: Предательство близкого человека
  ↓
LIE: "Любовь = уязвимость = боль"
  ↓
FLAW: Отталкивает людей, когда сближается
  ↓
NEED: Доверие без стен (FLAW мешает)
  ↓
WANT: Быть любимым (совместимо с LIE — "хочу любви, но боюсь близости")
```

Цепь замкнута — каждый элемент объясняется предыдущим.

Пример Елены — проверка SPINE → `[ref: part_04.md §4.6 — Проверка консистентности SPINE]` (canonical location примера).

### AP-10 · Перегрузка CoT · владелец §6.5 · уровень INTERMEDIATE

**Симптом:** больше 3 CoT-якорей в карточке.

**Причина:** попытка задать весь внутренний процесс.

**Исправление:** 2–3 CoT-якоря максимум, остальные — обычные T→A→P. Уровень CoT выбирается по модели — `[ref: part_06.md §6.2 — CoT Tiers]`; владелец правила якорей — `[ref: part_06.md §6.5 — CoT-якоря]`.

**ПРАВИЛО:** Модель генерирует внутренние монологи вместо действий, персонаж «думает» больше, чем «делает».

#### ❌ Перегрузка CoT

Карточка содержит 5 CoT-якорей. Модель тратит больше половины ответа на внутренний процесс → внешний ответ обеднён.

#### ✅ Максимум 2–3 CoT-якоря

Оставьте только ключевые триггеры (GHOST-связь, критический конфликт). Остальные якоря — обычные T→A→P без CoT.

### AP-11 · Переплетение голосов · владелец §3.5 · уровень EXPERT

**Симптом:** в мульти-персонажных сценах голоса смешиваются.

**Причина:** недостаточное различение голосов персонажей.

**Исправление:** маркеры персонажа (Character Markers) — явные маркеры уникальности голоса: специфичная лексика, синтаксические паттерны, телесные реакции, повторяющиеся фразы → `[ref: part_03.md §3.5 — Мульти-персонажные примеры]`. Утечка голоса в сторону нарратора — отдельный случай: `[ref: part_03.md §3.5 — Утечка голоса]`.

### AP-12 · Невалидный XML · владелец §7A.9/§7A.4 · уровень EXPERT

**Симптом:** невалидные XML-теги в Description.

**Причина:** опечатки, незакрытые теги.

**Исправление:** валидируйте XML перед использованием; одна система разметки — Format Lock → `[ref: part_07a.md §7A.9 — XML structure]` + `[ref: part_07a.md §7A.4 — Format Lock]`.

#### ❌ Неправильно

```
<spine>
WANT: {{want}}
<spine>
```

#### ✅ Правильно

```
<spine>
WANT: {{want}}
</spine>
```

### AP-13 · Конфликт Lorebook · владелец §7B.3 · уровень INTERMEDIATE

**Симптом:** записи Lorebook (база знаний) противоречат друг другу или Description.

**Причина:** независимое создание записей без проверки.

**Исправление:** проверяйте консистентность всех записей Lorebook с Description → `[ref: part_07b.md §7B.3 — Lorebook]`.

### AP-14 · Нарушение контекстного окна · владелец §7A.11/§7A.12 · уровень INTERMEDIATE

**Симптом:** карточка + контекст больше контекстного окна модели.

**Причина:** расширенная карточка для 4K-модели.

**Исправление:** 4K-Fallback Protocol или модель с большим контекстом → `[ref: part_07a.md §7A.11 — 4K-Fallback]` + `[ref: part_07a.md §7A.12 — Token Budget]`.

### AP-15 · Вложенные якоря · владелец §2.2 · уровень EXPERT

**Симптом:** якорь содержит вложенные условия: «Если X, а потом Y → делает Z» — модель не исполняет надёжно цепочку из 3+ вложенных условий на моделях до 14B.

**Причина:** попытка задать сложную поведенческую логику в одном якоре.

**Исправление:** разбейте на атомарные якоря — один якорь = одна связь T→A→P; принцип атомарности → `[ref: part_02.md §2.2 — поведенческие якоря]`.

#### ❌ Вложенный якорь / ✅ Атомарные якоря

```
❌ Вложенный: "Когда лгут → если уже лгали раньше → хлопает дверью → кричит: «Вон!»"
✅ Атомарные: "Когда лгут → сжимает челюсти → голос становится тише"
           + "Когда обнаруживает ложь повторно → хлопает дверью → уходит в другую комнату"
```

---

15 анти-паттернов покрывают ~90% ошибок сборки. Симптом → причина → исправление. Наиболее частые: AP-3 (голос в Description), AP-9 (сломанная SPINE), AP-15 (вложенные якоря).
