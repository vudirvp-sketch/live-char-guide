# Part 8: Anti-patterns (Анти-паттерны)

## 8.1 Анти-паттерны: каталог 15 ошибок

`data-section: p8_antipatterns_overview`

<!-- difficulty: INTERMEDIATE -->
<!-- canonical: Anti-pattern overview (15 APs) -->

**Анти-паттерн** — распространённая ошибка в создании карточки, приводящая к нестабильному поведению модели. Каждый анти-паттерн имеет симптом (что наблюдается), причину (почему возникает) и решение (как исправить).

**ПРАВИЛО:** Проверяйте карточку по этому списку перед тестом. Каждый анти-паттерн — частая ошибка, выявляемая на этапе валидации.

[VS: E12 — Antipattern Catalog. Сетка 5×3 с 15 AP-картами; каждая карта: AP-ID, severity dot (high/medium), симптом, причина, быстрый фикс, ссылка на раздел-владельца. **Canonical location** для сводного скана анти-паттернов; подробные разборы — §8.2. Тексты карт выровнены с разделами-владельцами (AP-1, AP-4, AP-8, AP-10, AP-11, AP-14, AP-15 — iter 173). Fix-императивы с числовыми значениями — SHARED_REFERENCE на канонических владельцев (AP-5 RepPen → §7A.6; паритет фиксирует `scripts/audit_sampling_parity.py`).]

**Как читать каталог.** Карточка — быстрый скан: симптом, причина, быстрый фикс. Разборы ниже добавляют к каждой ошибке то, чего в карточке нет: проверку, различающий сигнал или пример до/после.

## 8.2 Разборы: 15 анти-паттернов, проверка и пример

`data-section: p8_worked_examples`

<!-- difficulty: INTERMEDIATE -->

Один разбор = одна ошибка из каталога выше, развёрнутая до того, что нельзя уместить в карточку: проверка, различающий сигнал или пара «до/после».

### AP-1 · Раздувание токенов · BASIC

**ПРИМЕР:** Description 1200 токенов → модель игнорирует половину → персонаж теряет консистентность.

#### До/После: раздувание токенов — Елена

| ❌ Раздутый Description (600+ токенов) | ✅ Компактный Description (~250 токенов) |
|----------------------------------------|------------------------------------------|
| Елена — журналистка-расследователь. Она циничная и недоверчивая, но за её сарказмом скрывается уязвимость. Когда-то она доверяла людям, но предательство редактора сломало её веру в людей. Она говорит короткими фразами и использует сарказм как защиту. Её глаза сужаются, когда кто-то лжёт. Она трёт шею, когда нервничает. Она отталкивает людей, когда они становятся слишком близко... *(и так далее, повторяя Anchors, SPINE и голос в Description)* | `<identity>`Елена — журналистка-расследователь. Циничная, недоверчивая.`</identity>` `<spine>`WANT: Доказать правоту. NEED: Принятие. FLAW: Отталкивает сарказмом при близости. LIE: "Мне не нужно одобрение." GHOST: Предательство редактора.`</spine>` `<ocean>`O:72 C:65 E:41 A:38 N:68`</ocean>` Факты + Anchors + SPINE. Голос → Examples. |

### AP-2 · Отсутствующая цена · BASIC

**Проверка:** прочитайте якорь вслух и спросите: «что в этой сцене увидит собеседник?» Если ответа нет — цены нет. «Потом пожалеет», «устаёт от людей» — не цены: они не наблюдаемы в текущей сцене.

### AP-3 · Голос в Description · INTERMEDIATE

#### До/После: голос в Description — Елена

| ❌ Голос в Description | ✅ Голос в Examples |
|------------------------|----------------------|
| Description: "Елена говорит с сарказмом, использует короткие фразы и слово 'чувак'. Она отшучивается, когда ей некомфортно." *Модель проигнорирует стилистические директивы — голос не появится в генерации.* | Description: "Елена — журналистка-расследователь. Циничная, недоверчивая." Example: `<START>` Она отложила чашку и посмотрела в окно. Дождь барабанил по стеклу. "Опять. Третий день подряд." *Сарказм, короткие фразы, конкретная деталь — голос демонстрируется, не описывается.* |

### AP-4 · Психология в SP · BASIC

**ПРАВИЛО:** Модель не следует инструкциям о психологии. Психология должна быть в контексте (Description) — как структурированные теги (`<spine>`, `<ocean>`, `<enneagram>`), не нарративом — не в инструкциях (SP).

### AP-5 · RepPen > 1.10 · INTERMEDIATE

**Различающий сигнал:** персонаж «теряет» фирменные повторы и речевые маркеры, но лексика остаётся богатой — это RepPen, а не слабые Examples (при слабых Examples голос пустой с самого начала).

### AP-6 · Отсутствие анти-годмодинга · BASIC

В SP нужны две строки — запрет и позитивная формулировка:

```
Never speak or act for {{user}}.
```

**До/После:** `{{user}} подошёл. *Она почувствовала, как сердце user забилось чаще.*` ❌ → `{{user}} подошёл. *Она отступила на шаг.* «Так... и что теперь?»` ✅

Позитивная формулировка ("respond only to observable actions") работает лучше чистого запрета.

### AP-7 · Presence Penalty > 0 · INTERMEDIATE

**Различающий сигнал:** персонаж избегает тем, которые сам поднимал 2–3 реплики назад, и «расползается» на новые — при этом одиночные реплики остаются в характере. В Ollama/LM Studio PP захардкожен 0.7 — проверьте настройки интерфейса: KoboldCPP, TabbyAPI и vLLM позволяют выставить PP = 0.0.

### AP-8 · Призрак без якорей · INTERMEDIATE

**ПРИМЕР:** Елена — призрак «предательство редактора» → якорь «Когда вопрос о лояльности → напрягается».

### AP-9 · Сломанный SPINE · EXPERT

#### ❌ Сломанный SPINE

```
GHOST: (отсутствует)  →  LIE: (отсутствует)  →  FLAW: Избегает близости
NEED: Нуждается в доверии  ←  WANT: Хочет быть любимым
```

желание совместимо с потребностью — нет конфликта. Дефект блокирует обе потребности — но откуда дефект? Без объяснения через ложь/призрак цепь разорвана.

**Критерий сломанной SPINE (broken SPINE)** (сохраняется как диагностика): «желание совместимо с потребностью — нет конфликта» + дефект не объяснён через ложь/призрак. Это не то же самое, что «призрак/ложь текстуально отсутствуют» — по Part 4, призрак и ложь могут быть **неявными** для простых персонажей. Диагностируйте сломанную SPINE по разрыву каузальной цепи (дефект без корня в лжи/призраке), а не по текстовому отсутствию элементов.

#### ✅ Цельный SPINE

```
GHOST: Предательство близкого человека
  ↓
LIE: "Любовь = уязвимость = боль"
  ↓
FLAW: Отталкивает людей, когда сближается
  ↓
NEED: Доверие без стен (FLAW мешает)
  ↓
WANT: Быть любимым (совместимо с LIE — "хочу любви, но боюсь близости")
```

Цепь замкнута — каждый элемент объясняется предыдущим.

### AP-10 · Перегрузка CoT · INTERMEDIATE

**НАБЛЮДЕНИЕ:** При перегрузке CoT модель генерирует внутренние монологи вместо действий — персонаж «думает» больше, чем «делает».

#### ❌ Перегрузка CoT

Карточка содержит 5 CoT-якорей. Модель тратит больше половины ответа на внутренний процесс → внешний ответ обеднён.

#### ✅ Максимум 2–3 CoT-якоря

Оставьте только ключевые триггеры (GHOST-связь, критический конфликт). Остальные якоря — обычные T→A→P без CoT.

### AP-11 · Переплетение голосов · EXPERT

Маркеры персонажа (Character Markers) — явные маркеры уникальности голоса: специфичная лексика, синтаксические паттерны, телесные реакции, повторяющиеся фразы. В мульти-персонажной сцене у каждого персонажа должно быть 3 непересекающихся маркера; если при чтении вслух реплики двух персонажей можно поменять местами — маркеров нет.

### AP-12 · Невалидный XML · EXPERT

#### ❌ Неправильно

```
<spine>
WANT: {{want}}
<spine>
```

#### ✅ Правильно

```
<spine>
WANT: {{want}}
</spine>
```

### AP-13 · Конфликт Lorebook · INTERMEDIATE

**Проверка:** выпишите из записей Lorebook всё, что касается внешности, биографии и отношений персонажа, и сравните с Description. Расхождение в факте (возраст, имя, событие) модель разрешит в пользу того блока, который попал в контекст первым, — и карточка начнёт противоречить себе.

### AP-14 · Нарушение контекстного окна · INTERMEDIATE

**Что делать:** минимальная конфигурация для 4K-контекста — System Prompt 80–100, Description 150–200, два Examples вместе 130–160, Greeting 50–80. CoT, интерпретации OCEAN и Lorebook отключаются, а не сжимаются до нечитаемого.

### AP-15 · Вложенные якоря · EXPERT

#### ❌ Вложенный якорь / ✅ Атомарные якоря

```
❌ Вложенный: "Когда лгут → если уже лгали раньше → хлопает дверью → кричит: «Вон!»"
✅ Атомарные: "Когда лгут → сжимает челюсти → голос становится тише"
           + "Когда обнаруживает ложь повторно → хлопает дверью → уходит в другую комнату"
```

---

15 анти-паттернов покрывают самые частые ошибки сборки. Симптом → причина → исправление. Наиболее частые: AP-3 (голос в Description), AP-9 (сломанная SPINE), AP-15 (вложенные якоря).
