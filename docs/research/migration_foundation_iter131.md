## 4. Visual-system embedded knowledge analysis (new research)

### 4.1 Method

Scripted extraction of every human-readable string from each prototype
(`visual-system/elements/E##.html`: SVG `<text>`, SVG `<title>`/`aria-label`,
header title/subtitle, footer badges, mini-map labels, all text in `<main>`
outside SVG) and from the matching master VS-EMBED block
(`<div class="vs-embed" data-vs-element="E##">` … `<!-- REPLACED BY VISUAL
SYSTEM: E## -->`). Each embed string was checked for verbatim presence
(normalized) in the part's canon file. Full JSON inventory kept outside the
repo; per-element results are in `migration_map_v2.md` Registry A.

### 4.2 Aggregate result (FACT)

- Prototype strings: **529**; master-embed strings: **532**; **identical: 494
  (93% of embeds)** → the prototype layer is a near-verbatim second copy of the
  production embed layer, with no mechanism keeping them equal.
- Embed strings vs canon: **170 verbatim in canon (32%)**, 56 short
  labels/numbers, **337 (63%) NOT present in canon**.
- Per-element embed canon-coverage (exact / not-in-canon): E01 10/27 ·
  E02 10/19 · E03 3/19 · E04 9/10 · E05 12/16 · E06 3/10 · E07 6/20 ·
  E08 10/7 · E09 7/9 · E10 5/12 · E11 12/24 · E12 23/38 · E13 3/37 ·
  E14 9/9 · E15 3/42 · E16 9/20 · E17 25/13 · E18 11/5.

INFERENCE — the visual system is a **knowledge source, not a decoration layer**:
two thirds of its embedded text has no textual canonical home. This
independently confirms the owner's hypothesis and changes the v2 design
constraint: the v2 architecture must either give these payloads a canonical
textual owner, declare them visual-canonical (knowledge lives once, in the
visual), or consciously discard them as presentation/leakage — per element,
not wholesale.

## 6. First bounded area for architectural migration (PROPOSAL)

Criterion (owner): the next step must **reduce uncertainty or directly advance
a provable v1 → v2 migration**. v1 is frozen, so the bounded area must be a
v2-side build slice that demonstrates the full v2 pattern
(one canonical definition + derived/reference layers) end-to-end.

**Recommended first bounded area: the Glossary cluster (5.3).**

Rationale (FACT-based):
1. Most self-contained cluster — a term registry with no deep prose
   entanglement; ~80 disposition rows total (55 JSON + 25 canon − 21 overlap).
2. Largest competing-copies problem among clusters that need **no numeric
   content decision** — the unification mechanism is architectural; only the
   term-set composition needs an owner call.
3. Directly implements the v2 **Reference** reader mode backbone
   («найти конкретное правило или термин без линейного чтения»).
4. The runtime delivery path already exists and is healthy (panel + no-JS page,
   §5.3); v2 needs to re-point them at a single source, not build new plumbing.
5. All dead layers identified (core_rules array, never-loaded appendix) —
   maximal uncertainty reduction per effort.

Alternatives tested (owner-task §"Research discipline"):
- **CORE DIRECTIVES (5.1):** strong v2-pattern exemplar and pre-approved
  mechanism (ed-2, DEC-08), but executing it as a v1 edit violates the
  migration freeze; as a v2 slice it drags Part 10 + assembly + glossary
  dependencies — a wider blast radius than the glossary. → second bounded area.
- **Sampling values (5.2):** smallest cluster, but blocked on an owner value
  decision; zero architectural uncertainty reduction while blocked. → fold
  into the Part 7A v2 slice.
- **E13 diagnostics (5.4):** highest Debug-mode value, but requires a
  reconciliation content decision (E13 mappings vs §9.5/§9.6 tables). →
  third bounded area, decision packaged in the map's Registry B.

**Owner decision points for the first bounded area** (recorded in
`migration_map_v2.md` §6): (a) canonical term-set composition (25 canon vs
55 JSON vs merged — evidence table in Registry B); (b) source-of-truth
direction for the machine layer (canon MD stays source + JSON becomes
generated, vs JSON becomes source + MD generated); (c) disposition of the
never-loaded appendix layer (rides KI#70's wire-or-drop question, now an
input to the v2 Reference-mode design, not an auto-candidate).
