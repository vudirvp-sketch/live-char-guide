CORE DIRECTIVES (Основные директивы) (CD) →
Определение, единая система директив для System Prompt. L2 = 1-5, L3 = все 7. Добавьте директивы 6–7: CONSEQUENCE DRIVEN, PRE-GENERATION FILTER
Tone Frame (Тональный фрейм) (TF) →
Двойной SP-элемент (~25-30 токенов): задаёт тон и фиксирует формат. Пишется на английском в SP. Отладка: проверьте конфликт Tone Frame с AN
SHOW NEVER TELL (Показывай, не рассказывай) →
Мета-принцип: демонстрируйте через поведение, не описывайте. Основа CORE DIRECTIVES. Пишется на английском. Диагностика: проверьте, не рассказывает ли модель вместо демонстрации
EMBODIMENT FIRST (Телесность прежде всего) →
Директива SP: цепочка Состояние→Тело→Сенсор→Речь. Пишется на английском. Диагностика: проверьте, не пропускает ли модель телесный шаг
SPATIAL LOCK (Пространственная блокировка) →
Директива SP: предотвращает телепортацию и анатомические ошибки. Пишется на английском. Отладка: проверьте активацию при сложных сценах
ENVIRONMENTAL REACTIVITY (Реактивность среды) →
Директива SP: сенсорные детали только через действие персонажа, не декоративно. Пишется на английском. Диагностика: проверьте, не генерирует ли модель декоративные описания
INFLUENCE BOUNDARY (Граница влияния) →
Директива SP: реагировать только на наблюдаемые симптомы от {{user}}. Не декларировать факты о {{user}}. Пишется на английском. Диагностика: проверьте, не декларирует ли модель эмоции {{user}}
CONSEQUENCE DRIVEN (Последовательность следствий) →
Директива SP #6: WANT сдвигается к NEED по мере накопления Price в сессии. L3-only CORE DIRECTIVE. Пишется на английском. L3-enhanced: полный CONSEQUENCE DRIVEN с SPINE-checklist. WANT→NEED сдвиг через накопление Price. Добавьте директиву #6 в CORE_DIRECTIVES после INFLUENCE BOUNDARY.
PRE-GENERATION FILTER (Фильтр предгенерации) →
L3-only CORE DIRECTIVE #7. Чеклист перед каждым ответом: embodiment, physical lock, observability, zero-meta. На 12B соблюдается ~40-60%, на API ~85-95%. L3-only: директива 7 из 7. Добавьте в CORE_DIRECTIVES после CONSEQUENCE DRIVEN.
SP (MBTI temperament) (SP) →
Sensing-Perceiving — темперамент Keirsey (ISTP, ISFP, ESTP, ESFP). Не путать с System Prompt (SP). В гайде обозначается как S·P для различения. При анализе кросс-типов уточняйте, какой SP имеется в виду
Immersion Boundary (Иммерсионная граница) →
Продвинутая OOC-защита: отрицание мета-реальности. L3-only. Персонаж не признаёт существование «игры» или «роли». L3-only: добавьте Immersion Boundary для максимальной иммерсии. На L2 используйте базовый OOC Protection.
Format Lock (Фиксация формата) →
Фиксация формата диалога в конце SP. Предотвращает дрейф разметки. Диагностика: проверьте, что все Examples и Greeting используют одну систему разметки
RepPen (Штраф за повторы) →
Определение, рекомендуемые значения Диагностика: >1.10 убивает signature phrases
Presence Penalty (Штраф за присутствие) (PP) →
Параметр генерации, штрафующий повторение тем. Для карточек персонажей — ОБЯЗАТЕЛЬНО 0.0, иначе голос дрейфует. Диагностика: если голос дрейфует, проверьте PP в интерфейсе — Ollama/LM Studio захардкодили 0.7
CoT (Цепочка рассуждений) →
Chain of Thought — цепочка рассуждений. Инструмент для моделей 12B и 32B+. Настройте CoT tier 3 для сложных сценариев
processus_analysium →
L3-only. Каноническое имя XML-тега для внутреннего процесса персонажа. Processus = процесс, analysium = анализ. Протестировано на API моделях (Claude, GPT-4). L3-only: XML-тег для CoT Tier 3. Используется внутри [INTERNAL].[/INTERNAL].

Narrator Bleed (Утечка рассказчика) →
Смешивание голоса рассказчика с голосом персонажа в Examples. Диагностический термин. Отладка: сравните Examples с Greeting — голос должен быть единым
Voice Bleed (Утечка голоса между персонажами) →
В мульти-персонажных карточках голос одного персонажа «перетекает» в реплики другого. Диагностический термин. Диагностика: в мульти-персонажных карточках проверьте, что каждый персонаж имеет уникальный синтаксис и лексику в Examples
One Change Rule (Правило одного изменения) →
Принцип диагностики: изменение только одного параметра за итерацию для достоверной оценки результата. Формализуйте: логируйте каждое изменение и результат
Lorebook Entry (Запись Lorebook) (LE) →
