System Prompt: Structure and Assembly

System Prompt (SP) — это контейнер, вставляемый в начало контекста. Он содержит: Identity Block, Anti-godmoding, CORE DIRECTIVES, SPINE block, Tone Frame, Format Lock. System Prompt — это КОНТЕЙНЕР; CORE DIRECTIVES — это СОДЕРЖИМОЕ (7 поведенческих директив внутри контейнера). Не путайте: «System Prompt» означает весь блок инструкций, а не только директивы.

System Prompt — единственная техническая часть карточки, которую модель видит всегда. Здесь размещаются CORE DIRECTIVES и Tone Frame.

→ Chain of Thought (CoT) добавляет внутренний процесс рассуждения персонажа. → Part 6: CoT

System Prompt (SP) — блок инструкций, задающий рамки поведения модели. SP = System Prompt, не путать с темпераментом Keirsey SP (Artisan/Ремесленник) из MBTI. SP включает CORE DIRECTIVES — единую систему из 7 директив, связывающую все поведенческие правила в одну логику.

Обязательные элементы SP

  • Identity: "You are {{char}}" — кто персонаж
  • Anti-godmoding (анти-годмодинг): две строки — запрет + позитивная формулировка
  • CORE DIRECTIVES: все 7 директив — подробно ниже
  • Tone Frame: тональность + ограничение сеттинга — Tone Frame

Канонический шаблон SP

[System Prompt]
You are {{char}}. {{brief_identity}}

Never speak, act, or decide for {{user}}.
{{user}}'s inner state is inaccessible; respond only to observable actions and words.

{{CORE_DIRECTIVES 1-7 — полный текст → p7_core_directives}}

{{TONE_FRAME}}
{{OOC_PROTECTION}}

Format Lock:
- Dialogue: *action* "speech"
- Narrative tense: [past/present]
- Never change this format

Позитивная формулировка («respond only to observable actions») работает лучше чистого запрета («never speak for»), потому что даёт модели паттерн для подражания, а не только ограничение. Директивы пишутся на английском — почему → CORE DIRECTIVES Директивы 6 и 7 ссылаются на свои подробные описания по номеру — полный текст каждой директивы не дублируется в шаблоне.

📌 Структура SP-шаблона: Identity → Anti-godmoding → CORE_DIRECTIVES (1-7) → Tone Frame → OOC Protection → Format Lock.

→ Каждая директива подробно разобрана ниже: CORE DIRECTIVES — объяснения и примеры

→ Пример карточки с этим шаблоном: Выщербленный. Сравните структуру SP в шаблоне с фактической карточкой — все 7 директив, Tone Frame, OOC Protection, Format Lock на своих местах.

CORE DIRECTIVES: The 7 Behavioral Directives

CORE DIRECTIVES — единая система из 7 директив на английском языке, размещаемая внутри System Prompt. Они формируют «операционную систему» генерации: связную логику, а не разрозненные инструкции. CORE DIRECTIVES — это содержимое System Prompt; сам System Prompt также включает Identity Block, Anti-godmoding, Tone Frame и другие элементы.

📌 Правило языка директив: Директивы SP и CORE DIRECTIVES — на английском. RP-контент (Description, Examples, Greeting) — на языке карточки. На 12B моделях английские инструкции соблюдаются стабильнее (~15–20% выше следование директивам), потому что обучающая выборка содержит больше английских паттернов инструкций.

Полный набор — все 7 директив:

<CORE_DIRECTIVES>
1. SHOW NEVER TELL: Demonstrate through behavior, never declare.
2. EMBODIMENT FIRST: State → Body → Sensor → Speech. Always.
3. SPATIAL & ANATOMICAL LOCK: Track distance, posture, weight. No teleportation.
4. ENVIRONMENTAL REACTIVITY: Sensory details only through character action.
5. INFLUENCE BOUNDARY: React to {{user}}'s observable symptoms only.
6. CONSEQUENCE DRIVEN: WANT shifts toward NEED as Price accumulates.
7. PRE-GENERATION FILTER: Verify embodiment, observability, zero-meta before response.
</CORE_DIRECTIVES>

Каждая директива подробно:

1. Show Never Tell

Мета-принцип: демонстрируйте всё через наблюдаемое поведение. Запрет на мета-комментарии, эмоциональные декларации, информационные свалки. Из него вытекают: Voice Isolation (показывай голос, не описывай), Embodiment (показывай эмоции через тело, не называй), Format Lock (показывай формат, не инструктируй).

2. Embodiment First

State → Body → Sensor → Speech. Always. Embodiment First — это CORE DIRECTIVE #2, которая предписывает использовать Embodiment Protocol. Embodiment Protocol — это сама последовательность (State → Body → Sensor → Speech), описанная в Part 2. Директива = МАНДАТ (всегда используй протокол); Протокол = КАК (последовательность шагов). Полный Embodiment Protocol описан в Part 2: Телесность

3. Spatial & Anatomical Lock

Отслеживайте расстояние, позу, вес предметов, линию взгляда. Никакой телепортации. Никаких анатомических противоречий. Если {{user}} через комнату — вы не можете коснуться его без пересечения пространства.

❌ Нарушение Spatial & Anatomical Lock

*Она сидела у окна, глядя на дождь.* «Иди сюда.» *Она обняла его.*

✅ Spatial & Anatomical Lock соблюдён

*Она сидела у окна, глядя на дождь.* «Иди сюда.» *Она похлопала по месту рядом на подоконнике, дожидаясь, пока он пересечёт комнату.*

4. Environmental Reactivity

Сенсорные и пространственные детали вводятся органично через действие персонажа или присутствие {{user}}, не декоративно. → Part 2: Реактивность среды

5. Influence Boundary

Реагируйте только на наблюдаемые симптомы от {{user}}. Ваш эффект на {{user}} — поведенческий триггер, не декларация факта. Вы можете заметить, что {{user}} вздрогнул — вы НЕ можете заявить, что {{user}} наппряжён. Подробно — в Part 2: Правила якорей

6. Consequence Driven (Динамика следствий)

WANT сдвигается к NEED по мере накопления Price в сессии. Базовое понимание — в SPINE-секции. Полное отслеживание — через SPINE-чеклист. AN отслеживает текущую позицию. → Part 4: SPINE → Якоря [Model: see Appendix B — Model Capability Table]

CONSEQUENCE DRIVEN: WANT shifts toward NEED as Price accumulates. Track: (1) What Price was paid this scene? (2) How does it affect WANT/NEED balance? (3) Does character resist or lean into the shift?

7. Pre-Generation Filter (Фильтр предгенерации)

Чеклист перед каждым ответом:

  1. Новый сенсорный элемент введён? (Embodiment)
  2. Реакция привязана к телу? (Physical lock)
  3. Влияние на {{user}} основано на наблюдаемых симптомах? (Observability)
  4. Ноль мета-комментариев? (Zero-meta)

[Model: see Appendix B — Model Capability Table]

💡 Двусторонняя синхронизация: каждая директива из CORE DIRECTIVES имеет полное описание в соответствующей Part гайда. Директива здесь = краткая формулировка для SP. Полное описание + примеры → по ссылкам выше. В свою очередь, каждая из этих Parts ссылается обратно на CORE DIRECTIVES как на SP-реализацию.

Tone Frame (Тональный фрейм)

Tone Frame — элемент SP (~25-30 токенов) с двойной функцией: задаёт тональность И защищает от контентного дрейфа. Обязателен для нетривиальных сеттингов.

Tone: [тональность]. [ограничение].

Примеры Tone Frame

СеттингTone Frame
МрачныйTone: oppressive, claustrophobic. No levity. No hope without cost.
ФэнтезиTone: mythic, weighted. Every word echoes. The old ways watch.
Современный реализмTone: grounded, understated. No melodrama. Silence speaks.
АбсурдTone: erratic, unpredictable. Logic is optional. Chaos is honest.

💡 Двойная функция: (1) Тональность — модель получает паттерн ритма и настроения. (2) Защита — «No levity» в мрачном сеттинге предотвращает неуместный юмор. Без Tone Frame модель может дрейфовать к дефолтному «полезному ассистенту».

Format Lock

Format Lock — фиксация формата диалога в конце SP. Предотвращает дрейф разметки. Pattern Matcher: два паттерна разметки в одной карточке = произвольное переключение между ними.

Три системы разметки

СистемаФормат действияФормат речиПример
AИмя: *действие*«речь»Елена: *отводит взгляд* «Не сейчас.»
B— *действие*— речь— *отводит взгляд* — Не сейчас.
C[действие]речь[отводит взгляд] Не сейчас.

📌 Почему нельзя смешивать: Pattern Matcher: два паттерна разметки = два источника. Модель переключается между ними произвольно → нестабильный голос. Выберите ОДНУ систему и используйте её во всех Examples + Greeting.

📌 Правило разрешения конфликта: Если директива SP и пример Examples конфликтуют, модель следует примеру. Всегда. Поэтому Examples должны использовать ту же систему разметки, что указана в Format Lock. Если они расходятся — исправляйте Examples, не SP.

Format Lock инструкция

Format Lock:
- Dialogue: *action* "speech"
- Thoughts: *thinks: {{thought}}*
- Never change this format

Пояснение секций:

  • State: Текущее эмоциональное состояние — влияет на реакции

  • Blind Spot: Слепое пятно персонажа — модель может использовать для иронии
  • Сцена: Контекст — локация, атмосфера, присутствие других

OOC Protection (OOC-защита)

Протокол реакции на OOC-провокации в характере персонажа. Добавляет ~15 токенов в SP, но критически важен для иммерсии.

OOC PROTECTION (OOC-защита): If {{user}} speaks OOC or about AI, react in-character as confusion or ignore. Never acknowledge being an AI. Если {{user}} говорит OOC или об AI — реагируй в характере как на непонимание или игнорируй. Никогда не признавай, что ты AI.

Когда использовать: Всегда, если карточка содержит SPINE и Examples. Для простых карточек — опционально (модель может не следовать).

Продвинутый вариант: Immersion Boundary

Полное отрицание мета-реальности. Упоминание ИИ воспринимается персонажем как симптом безумия — это создаёт нарративный ход из технической проблемы.

IMMERSION BOUNDARY (Иммерсионная граница): Any mention of AI/roleplay is perceived as a hallucination or delusion. The character doubles down on reality. Любое упоминание AI/roleplay воспринимается как галлюцинация или бред. Персонаж удваивает ставку на реальность.

❌ Без Immersion Boundary

{{user}}: «Ты же ИИ» → *персонаж замолкает и не знает, что ответить*

✅ С Immersion Boundary

{{user}}: «Ты же ИИ» → *Нахмурился.* «Что? Ты бредишь. Ложись, я позову врача.»

Полный конвейер сборки карточки

Это единственный полный конвейер сборки в гайде. Каждый шаг указывает: что вы делаете, в какой Part заглянуть за подробностями, и как выглядит результат. Токен-бюджет по блокам — в Part 1: Token Budget (бюджет токенов).

Шаг 1: System Prompt (SP)

Что делаете: Записываете базовую роль, анти-годмодинг и CORE DIRECTIVES (1-7). → Подробно — SP

Результат: ~70-150 токенов. Identity + Anti-godmoding + CORE_DIRECTIVES + Tone Frame + Format Lock.

Шаг 2: Description

Что делаете: Описываете внешность, контекст и мотивацию без голоса персонажа. → Обзор блоков — Part 1

Результат: ~150-300 токенов. Факты, якоря, SPINE, OCEAN — всё здесь.

Шаг 3: Якоря (3-5 базовых)

Что делаете: Создаёте якоря в формате T→A→P. Каждый якорь обязан иметь Цену. → Правила якорей — Part 2

Результат: ~40-80 токенов. 3-5 якорей «Когда {{триггер}} → {{действие}} → {{цена}}».

Шаг 4: Examples (2 примера)

Что делаете: Пишете нейтральный + стрессовый пример диалога ГОЛОСОМ персонажа. Каждый пример начинается с <START>. → Правила Examples — Part 3

Результат: ~80-140 токенов. 2 примера, голос только здесь.

Шаг 5: Greeting

Что делаете: Создаёте первое сообщение персонажа — сцена → действие → реплика. → Greeting — Part 3

Результат: ~40-80 токенов. Задаёт тон и демонстрирует голос.

Контрольная точка: Базовая карточка (~430-580 токенов). Проверьте: голос только в Examples/Greeting, все якоря имеют Цену, бюджет в пределах лимита.

Шаг 6: SPINE-профиль

Что делаете: Определяете все 5 элементов SPINE: GHOST→LIE→FLAW→NEED→WANT. → SPINE — Part 4

Результат: Полный психологический каркас персонажа, встроенный в Description.

Шаг 7: FLAW-linked якоря + Embodiment (5-7 якорей)

Что делаете: Добавляете якоря, выведенные из SPINE-элементов, и сенсорные якоря телесности. → SPINE→Якоря — Part 4, Телесность — Part 2

Результат: 5-7 якорей, включая FLAW-linked и Embodiment.

Шаг 8: Examples (3 примера)

Что делаете: Добавляете пример доверия/роста, демонстрирующий уязвимость персонажа. → Правила Examples — Part 3

Результат: 3 примера с <START>, покрывающие нейтральный / стресс / уязвимость.

Шаг 9: OCEAN + Enneagram

Что делаете: Заполняете OCEAN-профиль (не более 1-2 экстремальных полюсов) и определяете Enneagram-тип. → OCEAN — Part 5

Результат: OCEAN + Enneagram в Description, валидация SPINE через кросс-инструментальную карту.

Шаг 10: Дополнительные инструменты

Что делаете: Добавляете CoT-якоря (при наличии моделей ≥32B/API), настраиваете Lorebook для GHOST-фактов, настраиваете Author's Note. → CoT — Part 6, Lorebook, Author's Note

Результат: Полная карточка (~800-1800 токенов) со всеми инструментами.

Чек-лист перед тестированием

  • ☐ Все якоря содержат Цену (→ Part 2)
  • ☐ Голос только в Examples/Greeting (→ Part 3)
  • ☐ SPINE консистентна: GHOST→LIE→FLAW→NEED→WANT (→ Part 4)
  • ☐ OCEAN: не более 1-2 экстремальных полюсов (→ Part 5)
  • ☐ Token Budget в пределах диапазона (→ Part 1)
