Зачем системный подход?

Классический подход к созданию карточек — интуитивное заполнение Description. Системный подход — причинно-следственная архитектура, где каждый элемент производит наблюдаемое действие. Разница измерима.

ПараметрКлассический подходСистемный подход (SPINE)

Динамика персонажаСтатичное поведениеWANT→NEED сдвиг через Price — персонаж развивается в сессии

Методология: проценты отклонения и другие количественные оценки в гайде — эмпирические ориентиры авторов на основе тестирования ~50 карточек на 12B–32B моделях, не точные измерения. Воспринимайте их как качественные маркеры (стабилен / дрейфует / сломан). Подробный disclaimer — Part 3 §3.1: Voice Isolation.

Базовые блоки карточки

Карточка персонажа — это документ, который задаёт поведение ИИ-модели при ролевой игре. Но думать о ней нужно как о поведенческом движке: каждый элемент должен производить наблюдаемое действие, а не украшать описание. Карточка состоит из четырёх блоков, каждый из которых выполняет свою функцию.

Сквозной пример: На протяжении всего гайда мы будем строить карточку Елены — от базовых блоков до полной карточки со всеми инструментами. Это позволит увидеть, как каждый инструмент добавляет глубину персонажу.

RULE: О примерах и стиле

Этот гайд учит механике, не эстетике. Все примеры намеренно сухие — они иллюстрируют структурные принципы (причинность SPINE, триггеры Behavioral Anchors (поведенческие якоря), маркеры Voice, логику CoT), а не качество письма. Когда пример содержит нарративный язык («Дождь барабанил по стеклу»), он существует для демонстрации конкретной директивы (в данном случае Environmental Reactivity) и помечен соответствующим образом. Стиль вашего персонажа — качество прозы, глубина лора, сенсорная насыщенность — ваша_domain. Этот гайд гарантирует, что модель его уважает.

Три ключевых принципа

Эти принципы обязательны для всех карточек. Нарушение любого из них приводит к ухудшению качества генерации.

Ключевые термины (используются далее без перевыполнения):

  • Anchor (поведенческий якорь) — конкретное правило поведения в формате Trigger → Action → Price (см. Part 2).
  • Voice (голос) — уникальный стиль речи персонажа; задаётся только в Examples и Greeting (см. Part 3).
  • SPINE — психологический каркас из 5 элементов (GHOST/LIE/FLAW/NEED/WANT), см. Part 4.
  • OCEAN — модель личности из 5 измерений (O/C/E/A/N), см. Part 5.

RULE: Фундаментальный принцип: LLM = Pattern Matcher, не Исполнитель правил. Директива в SP без паттерна в Examples нестабильна на моделях ≤14B (~40–60% следование директивам). Поэтому Examples — главный инструмент, а Description — логика поведения.

  1. Anchor = Trigger → Action → Price — поведение задаётся Anchors, и у каждого Anchors обязательна Цена — физическая реакция в той же сцене. Без Цены Anchor = инструкция без паттерна → Part 2: Behavioral Anchors
  2. Голос — только в Examples и Greeting — модель считывает характер персонажа из примеров диалога, а не из описания. Description = логика поведения, Examples = паттерны голоса → Part 3: Voice Isolation
  3. Психология — только в Description — SPINE, OCEAN и другие психологические элементы размещаются исключительно в блоке Description, никогда в System Prompt → Part 4: SPINE, Part 5: OCEAN

Топ-3 критичные ошибки

Три самые частые ошибки начинающих, которые сильнее всего ломают качество карточки. Каждая разбирается подробно: симптом → причина → пошаговое исправление → пример до/после. Дополнительные проблемы → Диагностика: Дополнительные проблемы (Part 9).

Ошибка 1: Персонаж пишет за {{user}}

Симптом: Модель описывает действия, мысли и реплики {{user}}. Диалог превращается в монолог от двух лиц.

Причина: В System Prompt нет Anti-godmoding (анти-годмодинга).

Исправление: Добавьте в SP строку «Never speak or act for {{user}}.» Fix → Part 8: AP-6

Ошибка 2: Голос не соответствует описанию

Симптом: Вы описали персонажа как «лаконичного и холодного», но модель отвечает многословно и эмоционально.

Причина: Голос помещён в Description вместо Examples (правило #3). Модель — Pattern Matcher: она копирует паттерны из Examples, но почти не следует стилистическим директивам в Description.

Исправление: Полный разбор Voice Isolation → Part 3: Voice Isolation

Ошибка 3: Персонаж «слишком идеальный»

Симптом: Персонаж не проявляет уязвимость, не ошибается, реагирует «правильно» на все стимулы.

Причина: Anchors не имеют цены (Price). Без физической реакции Anchor = инструкция без паттерна.

Исправление: Критерии качества Anchors → Part 2: Behavioral Anchors

Synthesis: Если в карточке есть SP, Description, Examples, Greeting — она уже работает. Три правила (Anchor = T→A→P, голос только в Examples, психология только в Description) — единственное, что нельзя нарушать.
