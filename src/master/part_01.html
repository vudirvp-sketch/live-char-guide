Базовые блоки карточки

Карточка персонажа — это документ, который задаёт поведение ИИ-модели при ролевой игре. Но думать о ней нужно как о поведенческом движке: каждый элемент должен производить наблюдаемое действие, а не украшать описание. Карточка состоит из четырёх блоков, каждый из которых выполняет свою функцию.

Сквозной пример: На протяжении всего гайда мы будем строить карточку Елены — от базовых блоков до полной карточки со всеми инструментами. Это позволит увидеть, как каждый инструмент добавляет глубину персонажу.

О примерах и стиле

Этот гайд учит механике, не эстетике. Все примеры намеренно сухие — они иллюстрируют структурные принципы (причинность SPINE, триггеры якорей, маркеры Voice, логику CoT), а не качество письма. Когда пример содержит нарративный язык («Дождь барабанил по стеклу»), он существует для демонстрации конкретной директивы (в данном случае Environmental Reactivity) и помечен соответствующим образом. Стиль вашего персонажа — качество прозы, глубина лора, сенсорная насыщенность — ваша_domain. Этот гайд гарантирует, что модель его уважает.

Три ключевых принципа

Эти принципы обязательны для всех карточек. Нарушение любого из них приводит к ухудшению качества генерации.

📌 Фундаментальный принцип: LLM = Pattern Matcher, не Исполнитель правил. Директива в SP без паттерна в Examples нестабильна на моделях ≤14B (~40–60% следование директивам). Поэтому Examples — главный инструмент, а Description — логика поведения.

  1. Якорь = Trigger → Action → Price — поведение задаётся якорями, и у каждого якоря обязательна Цена — физическая реакция в той же сцене. Без Цены якорь = инструкция без паттерна → Part 2: Behavioral Anchors
  2. Голос — только в Examples и Greeting — модель считывает характер персонажа из примеров диалога, а не из описания. Description = логика поведения, Examples = паттерны голоса → Part 3: Voice Isolation
  3. Психология — только в Description — SPINE, OCEAN и другие психологические элементы размещаются исключительно в блоке Description, никогда в System Prompt → Part 4: SPINE, Part 5: OCEAN

→ Правило OCEAN: не более 1-2 экстремальных полюсов — описано в Part 5: OCEAN

Token Budget

Сборка карточки — это конвейер, где каждый блок получает свой токен-бюджет. Превышение бюджета любого блока вытесняет другие, и модель теряет контекст. Таблица ниже показывает канонический бюджет для каждого блока. Дополнительные блоки (Tone Frame, Format Lock, AN, Lorebook) описаны в Part 7A и Part 7B.

Лимиты по блокам

Каждый блок имеет три уровня бюджета: минимальный (4K-контекст), стандартный (8K+) и максимальный (16K+). Превышение максимального значения — признак раздувания, ведущий к потере контекста. Зелёный = компактно и эффективно, жёлтый = стандартный баланс, красный = риск раздувания — эти обозначения отражают влияние на общее качество, а не уровень сложности.

Топ-3 критичные ошибки

Три самые частые ошибки начинающих, которые сильнее всего ломают качество карточки. Каждая разбирается подробно: симптом → причина → пошаговое исправление → пример до/после. Дополнительные проблемы → Диагностика: Дополнительные проблемы (Part 9).

Ошибка 1: Персонаж пишет за {{user}}

Симптом: Модель описывает действия, мысли и реплики {{user}}. Диалог превращается в монолог от двух лиц.

Причина: В System Prompt нет анти-годмодинга.

Исправление: Добавьте в SP строку «Never speak or act for {{user}}.» (Подробный разбор → Part 7A: System Prompt | Part 8: AP-6)

Ошибка 2: Голос не соответствует описанию

Симптом: Вы описали персонажа как «лаконичного и холодного», но модель отвечает многословно и эмоционально.

Причина: Голос помещён в Description вместо Examples — правило #3. Модель — Pattern Matcher: она копирует паттерны из Examples, но почти не следует стилистическим директивам в Description.

Исправление: Полный разбор Voice Isolation → Part 3: Voice Isolation

Ошибка 3: Персонаж «слишком идеальный»

Симптом: Персонаж не проявляет уязвимость, не ошибается, реагирует «правильно» на все стимулы.

Причина: Якоря не имеют цены (Price). Без физической реакции якорь = инструкция без паттерна.

Исправление: Критерии качества якоря → Part 2: Behavioral Anchors

Проблемы #4 и #5 → Диагностика: Дополнительные проблемы (Part 9)
