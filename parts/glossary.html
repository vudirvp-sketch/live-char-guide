SPINE →

WANT →
Определение, отличие от NEED Диагностика: WANT должен вести к FLAW
NEED →
Определение, отличие от WANT Диагностика: NEED должен требовать преодоления FLAW
FLAW →
Определение, связь с GHOST и LIE Проверьте: FLAW должен быть поведением, не чертой характера
LIE →

GHOST →
Событие прошлого персонажа, сформировавшее LIE и FLAW (цепочка: GHOST → LIE → FLAW). 3-tier структура травмы для сложных персонажей. Диагностика: проверьте активацию GHOST через LB триггеры
GHOST Layers →
Трёхуровневая система GHOST. Расширяет одиночный GHOST-элемент SPINE в многослойную структуру для сложных персонажей. Диагностика: проверьте, что каждый слой связан с соответствующим LIE и FLAW

CORE DIRECTIVES (CD) →
Определение, единая система из 7 директив для System Prompt. Добавьте директивы 6–7: CONSEQUENCE DRIVEN, PRE-GENERATION FILTER
Tone Frame (TF) →
Двойной SP-элемент (~25-30 токенов): задаёт тон и фиксирует формат. Пишется на английском в SP. Отладка: проверьте конфликт Tone Frame с AN
Show Never Tell →
Мета-принцип: демонстрируйте через поведение, не описывайте. Основа CORE DIRECTIVES. Пишется на английском. Диагностика: проверьте, не рассказывает ли модель вместо демонстрации
Embodiment First →
Директива SP: цепочка Состояние→Тело→Сенсор→Речь. Пишется на английском. Диагностика: проверьте, не пропускает ли модель телесный шаг
Embodiment Protocol →
Техника реализации воплощения: State → Body → Sensor → Speech. Отличать от Embodiment First (директива). Embodiment Protocol — полная методика, Embodiment First — директива в SP.
Spatial & Anatomical Lock →
Директива SP: предотвращает телепортацию и анатомические ошибки. Пишется на английском. Отладка: проверьте активацию при сложных сценах
Environmental Reactivity →
Директива SP: сенсорные детали только через действие персонажа, не декоративно. Пишется на английском. Диагностика: проверьте, не генерирует ли модель декоративные описания
Influence Boundary →
Директива SP: реагировать только на наблюдаемые симптомы от {{user}}. Не декларировать факты о {{user}}. Пишется на английском. Диагностика: проверьте, не декларирует ли модель эмоции {{user}}
Consequence Driven →
Директива SP #4: WANT сдвигается к NEED по мере накопления Price в сессии. CORE DIRECTIVE. Пишется на английском. [MODEL_NOTE: Наибольший эффект на моделях ≥32B и API; на 12B эффект ограничен]
Pre-Generation Filter →
CORE DIRECTIVE #5. Чеклист перед каждым ответом: embodiment, physical lock, observability, zero-meta. На 12B соблюдается ~40-60%, на API ~85-95%. [MODEL_NOTE: Требует моделей ≥32B или API; 12B модели часто игнорируют эту директиву]
Identity Block →
Секция System Prompt, определяющая идентичность персонажа. Включает имя, внешность, предысторию, тип личности. НЕ «блок идентичности» / «identity section». Диагностика: проверьте, что Identity Block не дублирует Description
Token Budget →
Распределение токенов контекстного окна по компонентам System Prompt. Контролирует, какая часть контекста выделена на каждый блок карточки. Диагностика: проверьте, что Identity Block + CORE DIRECTIVES не превышают 40% бюджета
Anti-godmoding →
Директива SP, запрещающая модель писать за {{user}}. Позитивная формулировка в SP. Отличать от «годмодинг» (диагностический термин — сам факт нарушения). Диагностика: проверьте наличие Anti-godmoding в SP
годмодинг →
Определение, проявления Диагностика: отладка persistent годмодинг
SP (MBTI temperament) (SP) →
Sensing-Perceiving — темперамент Keirsey (ISTP, ISFP, ESTP, ESFP). Не путать с System Prompt (SP). В гайде обозначается как S·P для различения. При анализе кросс-типов уточняйте, какой SP имеется в виду
Immersion Boundary →
Продвинутая OOC-защита: отрицание мета-реальности. Персонаж не признаёт существование «игры» или «роли». Добавьте Immersion Boundary для максимальной иммерсии. Для базовой защиты используйте OOC Protection.
Format Lock →
Фиксация формата диалога в конце SP. Предотвращает дрейф разметки. Диагностика: проверьте, что все Examples и Greeting Message используют одну систему разметки
RepPen →
Определение, рекомендуемые значения Диагностика: >1.10 убивает signature phrases
Presence Penalty (PP) →
Параметр генерации, штрафующий повторение тем. Для карточек персонажей — ОБЯЗАТЕЛЬНО 0.0, иначе голос дрейфует. Диагностика: если голос дрейфует, проверьте PP в интерфейсе — Ollama/LM Studio захардкодили 0.7
CoT →
Chain of Thought — цепочка рассуждений. Инструмент для моделей 12B и 32B+. Настройте CoT tier 3 для сложных сценариев
processus_analysium →
Каноническое имя XML-тега для внутреннего процесса персонажа. Processus = процесс, analysium = анализ. Протестировано на API моделях (Claude, GPT-4). XML-тег для CoT Tier 3. Используется внутри [INTERNAL].[/INTERNAL].

Нарушение голоса персонажа на 12B, вызванное копированием чужих примеров. Диагностика: если голос «плывёт», проверьте источник Examples
Narrator Bleed →
Смешивание голоса рассказчика с голосом персонажа в Examples. Диагностический термин. Отладка: сравните Examples с Greeting Message — голос должен быть единым
Voice Bleed →
В мульти-персонажных карточках голос одного персонажа «перетекает» в реплики другого. Диагностический термин. Диагностика: в мульти-персонажных карточках проверьте, что каждый персонаж имеет уникальный синтаксис и лексику в Examples
One Change Rule →
Принцип диагностики: изменение только одного параметра за итерацию для достоверной оценки результата. Формализуйте: логируйте каждое изменение и результат
Lorebook Entry (LE) →
Отдельная запись в Lorebook с полями Key, Content, Position, Depth, Probability, Cooldown. Добавьте мировые записи для углубления сеттинга
