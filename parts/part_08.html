Анти-паттерны: каталог 15 ошибок

Анти-паттерн — распространённая ошибка в создании карточки, приводящая к нестабильному поведению модели. Каждый анти-паттерн имеет симптом (что наблюдается), причину (почему возникает) и решение (как исправить).

ПРАВИЛО: Проверяйте карточку по этому списку перед тестом. Каждый анти-паттерн — частая ошибка, выявляемая на этапе валидации.

AP-1 высокая серьёзность
Раздувание токенов
Description выходит за бюджет блока (§7A.12)
Исправление:
Сократите до бюджета Description. Перенесите детали в Lorebook.
AP-2 высокая серьёзность
Отсутствует Price
У Anchor нет последствия в той же сцене
Исправление:
Добавьте физический, внутри-сценовый Price каждому Anchor (§2.2).
AP-3 высокая серьёзность
Голос в Description
Голосовые паттерны записаны в блоке Description
Исправление:
Перенесите весь голос в Examples. Description = только факты (§3.1).
AP-4 высокая серьёзность
Психология в SP
Элементы SPINE помещены в System Prompt
Исправление:
Перенесите SPINE в Description. SP = только инструкции и запреты (§7A.1).
AP-5 средняя серьёзность
RepPen > 1.10
Repetition Penalty установлен слишком высоким
Исправление:
Держите RepPen в диапазоне своей модели — §7A.6 (никогда > 1.10). Используйте MinP вместо повышения RepPen.
AP-6 высокая серьёзность
Нет Anti-godmoding
Отсутствует 2-строчный anti-godmoding в SP
Исправление:
Добавьте негативную + позитивную строки ограничений в SP (§7A.1).
AP-7 средняя серьёзность
Presence Penalty > 0
PP > 0 нарушает согласованность персонажа
Исправление:
Установите PP = 0.0 всегда. Без исключений (Appendix E).
AP-8 средняя серьёзность
Призрак без якорей
GHOST описан, но нет якорей, выражающих его в поведении
Исправление:
Добавьте GHOST-linked якоря в тег <anchors> (Description) — минимум один на призрак (§4.6).
AP-9 высокая серьёзность
Нарушенный SPINE
Элементы SPINE не образуют причинную цепь
Исправление:
Проверьте причинный поток GHOST→LIE→FLAW→NEED→WANT (§4.6, §4.6).
AP-10 средняя серьёзность
Перегрузка CoT
Больше 3 CoT-якорей в карточке
Исправление:
Оставьте 2–3 CoT-якоря, остальные — обычные T→A→P. Уровень CoT — по модели (§6.2, §6.5).
AP-11 высокая серьёзность
Переплетение голосов
В мульти-персонажных сценах голоса смешиваются
Исправление:
Добавьте маркеры персонажа (Character Markers): лексика, синтаксис, телесные реакции, повторяющиеся фразы (§3.5).
AP-12 средняя серьёзность
Некорректный XML
Теги неправильно закрыты или вложены
Исправление:
Проверьте все XML-теги. Одна система разметки — Format Lock (§7A.9, §7A.4).
AP-13 средняя серьёзность
Конфликт Lorebook
Запись Lorebook противоречит Description
Исправление:
Проверьте все записи Lorebook на согласованность с Description (§7B.3).
AP-14 высокая серьёзность
Нарушение контекстного окна
Карточка + контекст превышают окно модели
Исправление:
4K-Fallback Protocol или модель с большим контекстом (§7A.11, §7A.12).
AP-15 средняя серьёзность
Вложенные Anchors
В одном якоре задана цепочка вложенных условий
Исправление:
Разбейте на атомарные якоря: один якорь = одна связь T→A→P (§2.2).

Как читать каталог. Карточка — быстрый скан: симптом, причина, быстрый фикс. Полный разбор каждого анти-паттерна — симптом, причина, проверка и пример до/после — в §8.2: разборы 15 анти-паттернов. Правило целиком остаётся у своего владельца (раздел-владелец указан в каждой карточке и в каждом разборе): каталог не переобъясняет канонические разделы.

OCEAN Overload ранее был AP-15, перенесён в Part 5 §5.1 (p5_ocean_basics). В каталоге E12 не отображается — см. Part 5: OCEAN.

Разборы: 15 анти-паттернов, симптом → исправление

Один разбор = три строки (симптом, причина, исправление со ссылкой на владельца) плюс только тот материал, которого нет в разделе-владельце: проверка, различающий сигнал или пример до/после. Правило целиком — по ссылке владельца; здесь — распознавание и применение.

AP-1 · Раздувание токенов · владелец §7A.12 · уровень BASIC

Симптом: Description выходит за бюджет блока.

Причина: избыточное описание, дублирование, голос в Description.

Исправление: сократите до бюджета Description, детали — в Lorebook. Владелец правила — Part 7A §7A.12 — бюджет токенов; голос → Part 3 §3.1 — изоляция голоса.

Пример: Description 1200 токенов → модель игнорирует половину → персонаж теряет консистентность.

❌ Раздутый Description (600+ токенов)

Елена — журналистка-расследователь. Она циничная и недоверчивая, но за её сарказмом скрывается уязвимость. Когда-то она доверяла людям, но предательство редактора сломало её веру в людей. Она говорит короткими фразами и использует сарказм как защиту. Её глаза сужаются, когда кто-то лжёт. Она трёт шею, когда нервничает. Она отталкивает людей, когда они становятся слишком близко... (и так далее, повторяя Anchors, SPINE и голос в Description)

✅ Компактный Description (~250 токенов)

<identity>Елена — журналистка-расследователь. Циничная, недоверчивая.</identity>
<spine>WANT: Доказать правоту. NEED: Принятие. FLAW: Отталкивает сарказмом при близости. LIE: "Мне не нужно одобрение." GHOST: Предательство редактора.</spine>
<ocean>O:72 C:65 E:41 A:38 N:68</ocean>

Факты + Anchors + SPINE. Голос → Examples.

Полная карточка Елены — Part 10: Елена.

AP-2 · Отсутствующая цена · владелец §2.2 · уровень BASIC

Симптом: у якоря (Anchor) нет физической цены.

Причина: у якоря нет последствия, наблюдаемого в той же сцене.

Исправление: формат якоря Триггер → Действие → Цена; каждый якорь обязан иметь Цену — без неё модель не показывает уязвимость → Part 2 §2.2 — поведенческие якоря.

Проверка: прочитайте якорь вслух и спросите: «что в этой сцене увидит собеседник?» Если ответа нет — цены нет. «Потом пожалеет», «устаёт от людей» — не цены: они не наблюдаемы в текущей сцене.

AP-3 · Голос в Description · владелец §3.1 · уровень INTERMEDIATE

Симптом: стилистические директивы в Description.

Причина: голос описан словами вместо демонстрации в примерах диалога.

Исправление: Description = только факты; голос → Examples/Greeting. Модель считывает характер из примеров диалога, а не из описания → Part 3 §3.1 — изоляция голоса.

❌ Голос в Description

Description: "Елена говорит с сарказмом, использует короткие фразы и слово 'чувак'. Она отшучивается, когда ей некомфортно."

Модель проигнорирует стилистические директивы — голос не появится в генерации.

✅ Голос в Examples

Description: "Елена — журналистка-расследователь. Циничная, недоверчивая."

Example:
<START>
Она отложила чашку и посмотрела в окно. Дождь барабанил по стеклу.
"Опять. Третий день подряд."

Сарказм, короткие фразы, конкретная деталь — голос демонстрируется, не описывается.

AP-4 · Психология в SP · владелец §7A.1 · уровень BASIC

Симптом: психологический анализ (SPINE, призрак) помещён в System Prompt.

Причина: попытка «проинструктировать» модель о характере.

Исправление: SPINE (WANT/NEED/дефект) и призрак — только в Description; SP = только инструкции и запреты → Part 7A §7A.1 — System Prompt.

ПРАВИЛО: Модель не следует инструкциям о психологии. Психология должна быть в контексте (Description) — как структурированные теги (<spine>, <ocean>, <enneagram>), не нарративом — не в инструкциях (SP).

AP-5 · RepPen > 1.10 · владелец §7A.6 · уровень INTERMEDIATE

Симптом: Repetition Penalty > 1.10.

Причина: превышение подавляет характерные речевые обороты персонажа — генерация становится монотонной.

Исправление: держите RepPen в диапазоне своей модели — §7A.6 (никогда > 1.10); повышайте MinP вместо RepPen → Part 7A §7A.6 — параметры генерации.

Различающий сигнал: персонаж «теряет» фирменные повторы и речевые маркеры, но лексика остаётся богатой — это RepPen, а не слабые Examples (при слабых Examples голос пустой с самого начала).

AP-6 · Отсутствие анти-годмодинга · владелец §7A.1 · уровень BASIC

Симптом: модель пишет за {{user}} — действия, мысли, чувства.

Причина: в SP нет директивы anti-godmoding.

Исправление: обязательно добавьте в SP две строки — запрет и позитивную формулировку → Part 7A §7A.1 — System Prompt:

Never speak or act for {{user}}.

До/После: {{user}} подошёл. *Она почувствовала, как сердце {{user}} забилось чаще.* ❌ → {{user}} подошёл. *Она отступила на шаг.* «Так... и что теперь?» ✅

Позитивная формулировка ("respond only to observable actions") работает лучше чистого запрета.

AP-7 · Presence Penalty > 0 · владелец §7A.6 · уровень INTERMEDIATE

Симптом: Presence Penalty > 0.

Причина: ненулевой PP заставляет модель вводить новые темы вместо удержания характерных паттернов персонажа.

Исправление: Presence Penalty = 0.0 для всех карточек персонажей → Part 7A §7A.6 — параметры генерации (значения — Appendix E).

Различающий сигнал: персонаж избегает тем, которые сам поднимал 2–3 реплики назад, и «расползается» на новые — при этом одиночные реплики остаются в характере. В Ollama/LM Studio PP захардкожен 0.7 — проверьте настройки интерфейса (Appendix E).

AP-8 · Призрак без якорей · владелец §4.6 · уровень INTERMEDIATE

Симптом: призрак (GHOST) описан, но нет якорей, связанных с ним.

Причина: призрак остаётся описанием, а не поведенческим драйвером.

Исправление: каждый GHOST = минимум один GHOST-linked якорь в теге <anchors> (Description); призрак — корень причинной цепочки SPINE, он должен выражаться в поведении через якорь → Part 4 §4.6 — SPINE → карта якорей.

Пример: Елена — призрак «предательство редактора» → якорь «Когда вопрос о лояльности → напрягается → желваки сжимаются, короткий выдох».

AP-9 · Сломанный SPINE · владелец §4.6 · уровень EXPERT

Симптом: SPINE-элементы не связаны логически — желание совместимо с потребностью (нет конфликта), дефект существует без объяснения.

Причина: желание, потребность, дефект, ложь, призрак написаны независимо, без причинно-следственной связи.

Исправление: проверьте цепочку GHOST → LIE → FLAW → NEED → WANT; каждый элемент объясняется предыдущим → Part 4 §4.6 — полная цепочка SPINE; проверка консистентности → Part 4 §4.6 — проверка SPINE.

❌ Сломанный SPINE

GHOST: (отсутствует)  →  LIE: (отсутствует)  →  FLAW: Избегает близости
NEED: Нуждается в доверии  ←  WANT: Хочет быть любимым

Здесь желание совместимо с потребностью — конфликта нет, и дефект не объяснён: без ложи/призрака цепь разорвана.

Критерий сломанной SPINE (broken SPINE) (сохраняется как диагностика): «желание совместимо с потребностью — нет конфликта» + дефект не объяснён через ложь/призрак. Это не то же самое, что «призрак/ложь текстуально отсутствуют» — по Part 4 §4.1, призрак и ложь могут быть неявными для простых персонажей. Диагностируйте сломанную SPINE по разрыву каузальной цепи (дефект без корня в лжи/призраке), а не по текстовому отсутствию элементов.

✅ Цельный SPINE

GHOST: Предательство близкого человека
  ↓
LIE: "Любовь = уязвимость = боль"
  ↓
FLAW: Отталкивает людей, когда сближается
  ↓
NEED: Доверие без стен (FLAW мешает)
  ↓
WANT: Быть любимым (совместимо с LIE — "хочу любви, но боюсь близости")

Цепь замкнута — каждый элемент объясняется предыдущим.

Пример Елены — проверка SPINE → Part 4 §4.6 — проверка консистентности SPINE.

AP-10 · Перегрузка CoT · владелец §6.5 · уровень INTERMEDIATE

Симптом: больше 3 CoT-якорей в карточке.

Причина: попытка задать весь внутренний процесс.

Исправление: 2–3 CoT-якоря максимум, остальные — обычные T→A→P. Уровень CoT выбирается по модели — Part 6 §6.2 — уровни CoT; владелец правила якорей — Part 6 §6.5 — CoT-якоря.

НАБЛЮДЕНИЕ: При перегрузке CoT модель генерирует внутренние монологи вместо действий — персонаж «думает» больше, чем «делает».

❌ Перегрузка CoT

Карточка содержит 5 CoT-якорей. Модель тратит больше половины ответа на внутренний процесс → внешний ответ обеднён.

✅ Максимум 2–3 CoT-якоря

Оставьте только ключевые триггеры (GHOST-связь, критический конфликт). Остальные якоря — обычные T→A→P без CoT.

AP-11 · Переплетение голосов · владелец §3.5 · уровень EXPERT

Симптом: в мульти-персонажных сценах голоса смешиваются.

Причина: недостаточное различение голосов персонажей.

Исправление: маркеры персонажа (Character Markers) — явные маркеры уникальности голоса: специфичная лексика, синтаксические паттерны, телесные реакции, повторяющиеся фразы → Part 3 §3.5 — мульти-персонажные примеры. Утечка голоса в сторону нарратора — отдельный случай: Part 3 §3.5 — утечка голоса.

AP-12 · Невалидный XML · владелец §7A.9/§7A.4 · уровень EXPERT

Симптом: невалидные XML-теги в Description.

Причина: опечатки, незакрытые теги.

Исправление: валидируйте XML перед использованием; одна система разметки — Format Lock → Part 7A §7A.9 — XML-теги + Part 7A §7A.4 — Format Lock.

❌ Неправильно:

<spine>
WANT: {{want}}
<spine>

✅ Правильно:

<spine>
WANT: {{want}}
</spine>
AP-13 · Конфликт Lorebook · владелец §7B.3 · уровень INTERMEDIATE

Симптом: записи Lorebook (база знаний) противоречат друг другу или Description.

Причина: независимое создание записей без проверки.

Исправление: проверяйте консистентность всех записей Lorebook с Description → Part 7B §7B.3 — Lorebook.

AP-14 · Нарушение контекстного окна · владелец §7A.11/§7A.12 · уровень INTERMEDIATE

Симптом: карточка + контекст больше контекстного окна модели.

Причина: расширенная карточка для 4K-модели.

Исправление: 4K-Fallback Protocol или модель с большим контекстом → Part 7A §7A.11 — 4K-Fallback + Part 7A §7A.12 — бюджет токенов.

AP-15 · Вложенные якоря · владелец §2.2 · уровень EXPERT

Симптом: якорь содержит вложенные условия: «Если X, а потом Y → делает Z» — модель не исполняет надёжно цепочку из 3+ вложенных условий на моделях до 14B.

Причина: попытка задать сложную поведенческую логику в одном якоре.

Исправление: разбейте на атомарные якоря — один якорь = одна связь T→A→P; принцип атомарности → Part 2 §2.2 — поведенческие якоря.

❌ Вложенный: "Когда лгут → если уже лгали раньше → хлопает дверью → кричит: «Вон!»"
✅ Атомарные: "Когда лгут → сжимает челюсти → голос становится тише"
           + "Когда обнаруживает ложь повторно → хлопает дверью → уходит в другую комнату"

15 анти-паттернов покрывают ~90% ошибок сборки. Симптом → причина → исправление. Наиболее частые: AP-3 (голос в Description), AP-9 (сломанная SPINE), AP-15 (вложенные якоря).
